## 做了什么（U17 = M3 的主干）
**一句话**：证明模板的参数不再写死成 `(群, p)` —— 控件由模板自己声明；
轨道–稳定子与第一同构两条模板落地，定理库从 3 条满到 5 条。

### 1. 参数槽（地基，改 `gal/proof.ts`）
- 新增 `ParamSlot` 四种：`prime`（|G| 的素因子按钮组，带 n_p）/ `element`（点 x）/
  `group`（靶群）/ `gens`（生成元的像）。
- `ProofTemplate` 加 `slots` 与 `suggest?(group, p, current)`；
  `build(group?, p?, extra?)` 第三个参数装槽值（**全是文本**，与定义行同一哲学）。
  `ProofParams.p` 转**可选**（OST 与第一同构都没有 p 可言）。
- `templateReady(t, group, p, extra?)` 收 extra；判据与 `build()` 共用**同一批纯函数**
  （`conjStage` / `mapStage`）——两处各写一遍迟早分叉。
- **为什么不做成 `build(params: Record<string,string>)` 一把梭**：`Sylow` 三条的
  `build` 已被 500+ 条断言与 `App.tsx` 按位置参数调用，改签名要全改且风险高。
  三参（群 / p / extra）丑一点，但现有调用一行未动。

### 2. 轨道–稳定子模板（`orbit-stabilizer`，8 步）
- 舞台选**共轭作用在自身上**（`共轭作用(G)`）：轨道 = 共轭类、稳定子 = 中心化子，
  `|G| = |O| · |Stab|` 是共轭类方程的雏形；舞台还只要一个参数（不必再挑子群）。
- 定义行 4 行：`G = S_4` / `A = 共轭作用(G)` / `O = 轨道(A, (234))` / `S = 稳定子(A, (234))`。
- **中心化子另算一遍做交叉核对**（`getCentralizer` 与 `稳定子(共轭作用)` 是两条 core 路径，
  实测给同一个数）→ 数字进文本。
- **交换群退化**（每个共轭类一个点）：模板在第 3 步**当场说清**"退化成 |G| = 1·|G|，
  想看真轨道就换非交换群"，而不是让用户看着 `|O| = 1` 发呆。
- 建议点：**共轭类最大**的元素，**跳过单位元**（单位元的共轭类恒为 `{e}`，最没看头）。
  实测：S₄→`(234)`、S₃→`(23)`、D₄→`r`、Q₈→`i`、C₆→`1`（退化但挑了个非平凡元素）。

### 3. 第一同构定理模板（`first-isomorphism`，11 步 / 满射 10 步）
- 只写三行：`G = C_6` / `H = C_6` / `φ = 映射(G, H, a→2)`，剩下 `φ/ker`、`φ/im`
  两个顶点与 π / ≅ / ↪ 三条边全由 `build.ts` + `derive.ts` 自动补。
- **模板绝不产出 `ker` / `im` 的定义行**：一旦写出来，`firstIsoObjects` 就把自动补点
  交还给用户 —— 那份"自动补全"的演示恰恰被自己写没了。断言守着这条。
- 核 / 像的阶由 `mapStage` 真算（`extendFromGenerators` + `verifyHomomorphism` +
  `computeKernelFromMapping`），与求值器同一批 core 函数。
- 建议的像（`suggestImages`）三档：
  ① 循环源 → 挑"像**真落在靶群内部**"的 y（图上才是正方形），并列取最大；
  ② 找不到就兜底给**满射**（三角形也比不给强）；③ 源 = 靶群（非循环）→ **恒等映射**
  （核平凡 ⇒ 商群 ≅ G，平凡但合法，至少卡片不是红的）。
  实测：C₆→C₆ = `a→2`、C₁₂→C₁₂ = `a→2`、C₆→C₃ = `a→1`（兜底满射）、
  A₄→A₄ = `a→(12)(34), b→(234)`（恒等）。

### 4. 面板（`ui/ProofDock.tsx`）
- 卡片按 `slots` 渲染控件；`drafts` 存用户改动、`suggestions` 存建议值（打底）；
  **换群 → 清空 drafts**（旧值对新群未必有意义）；**换靶群 → 重算同卡其它槽**
  （像 `a→2` 是相对靶群写的）但**不覆盖用户刚敲的那一格**。
- 运行头的实例行由 `instanceLabel()` 拼：`S_4 · x = (234)` / `C_6 · H = C_6 · a→2`。
- **空槽 = 引导（灰字 `.proof-hint`）· 填错 = 错误（红字 `.proof-bad`）**：
  非循环源上工具给不出像，一律红字会让人以为工具坏了。

## 本轮踩到的坑（都已补进 `verify/README.md`）
1. **`轨道(A, 1)` 的寻址看 Ω 是什么**：Ω = G 自身时按**元素记号**（S₄ 上没有叫 `1` 的元素 → 被拒），
   Ω 是集合（`Syl_p(G)` / 陪集）时才按 **1 起的数字下标**。M3 首轮就栽在这条，
   而且 C₆ 上**侥幸成功**（真有元素 `1`）—— 又一次"概率性正确"。
2. **循环群里单字母一律视作那个生成元**（`resolveElementLoose` 第 ③ 级）：
   `映射(G, H, a→x)` 在 C₆ 上**合法**（`x` ≡ `a`），拿它当"元素不存在"的反例会误判。
3. **轨道的值类型随 Ω 变**：Ω = G 自身 → `elements`；Ω 是集合 → `set`。
   只按 `set` 读成员数得 `-1`，看不出为什么（加了 `orbSize`）。
4. **面板把 `step.text` 当纯文本渲染**：模板里写 `**共轭类**` 会原样显示成两颗星
   （截图里露出来的）。要强调用「」。走查加了"文案不含 `**`"的哨兵。
5. **dev server 的 host**：`localhost` 在 Node 18+ 解析成 `::1`（只监听 IPv6），
   而走查脚本连 `127.0.0.1:5273` → `ERR_CONNECTION_REFUSED`，看着像"服务没起"。
   `vite.config.ts` 的 `server.host` 已写死 `127.0.0.1`。
6. **期望值按别的群类推**：`suggestImages('C_12','C_12')` 我按 C₆ 类推写成 `a→3`，
   实测是 `a→2`（`⟨2⟩` 阶 6 是最大非满像）。老规矩：期望值一律手算，别类推。

## 取舍记录
- 第一同构的**靶群默认 = 源群**（恒等映射兜底）而不是"挑一个有意思的商群"。
  理由：自动找"源→靶群的自然投影"要枚举正规子群再比对同构，成本高；
  恒等映射平凡但**合法且让卡片立即可跑**，用户想看点别的自己改像。
- OST 只给一条轨道（课本的 orbit–stabilizer 就是"一条轨道 + 稳定子"），
  没把 G 的全部共轭类摊开（那会稀释主线）。
- 没动 Sylow 三条模板的任何一行（只加了 `slots: [PRIME_SLOT]`），
  它们的断言一条没改（旧口径成了一条兼容性断言）。
