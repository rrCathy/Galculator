# 交互模型（INTERACTION）v2

> **Galculator 的 UI 规范来源**：对象与操作怎么输入、画布怎么展示、如何摆成交换图、操作入口长什么样。
> 并列文档：[ARCHITECTURE.md](ARCHITECTURE.md)（内核架构：值类型 / 10 原语 / 操作清单）· [PROOF_SPEC.md](PROOF_SPEC.md)（证明层）· [ROADMAP.md](ROADMAP.md)（U0–U7 / M0–M4）。
>
> v2 由 v1 与 `UI_PLAN`（已归档）合并而来，**5 条待拍板项已全部定案**（见 §13）。

## 0. 一句话

**用户应该在对象旁边完成他想要的操作。**

这是与 Desmos 最大的区别：Desmos 的画布是**输出**（你打字它画图）；Galculator 的画布是**操作台**（你在图上点对象、在它旁边选操作）。交换图本身可交互，是这个产品的身份。

## 1. 核心主张：画布 = 交换图

| | Desmos / GeoGebra | Galculator |
|---|---|---|
| 画布是什么 | 坐标系 | **交换图**（有向图）|
| 对象是什么 | 曲线 | **节点**（群 / 集合 / 作用）|
| 位置由什么定 | 数学（f 的取值）| **关系**（映射方向 / 派生深度）|
| 背景是什么 | 坐标网格 | 交换图版面（淡点阵，仅用于吸附）|
| 画布角色 | 输出 | **操作台** |

**用户不是在画图，是在"长"一张交换图。**

## 2. 一级对象与视觉编码

对象与内核的**值类型**一一对应（定义见 `apps/web/src/gal/value.ts`）：

**「去哪」由存在层级（`ValueSort`）决定，不再由各类型自己 switch**（DIAGRAM_SPEC §3）：

| 值类型 | 存在层级 | 形状 | 例子 |
|---|---|---|---|
| `group` | **vertex** | 方 | `D_4`、`G/N`、`Aut(G)`、`Z(G)`、`⟨S⟩` |
| `elements` | **vertex** | 圆 | `A ∩ B`、`A · B`、轨道、不动点 |
| `set` | **vertex** | 圆 | `底集(Syl(G,2))` —— 群作用的 Ω |
| `map` | **edge** | **实线箭头**（不占节点）| `f : G → H` |
| `action` | **edge** | 作用线 `G ↷ Ω`（**可点选**；Ω = G 时画成 G 上的自环）| `共轭作用(G)` · `共轭作用在(G, Ω)` |
| `set` | **vertex** | 圆 | `底集(Syl_p(G))` —— 群作用的 Ω |
| `subgroups` | **list** | — | `Sub(G)`、`pSub(G,2)`、`Syl(G,2)` → **不上画布** |
| `number` | **scalar** | — | 进左下方「数值」区 |

> **判据**：能作为某个映射的源或靶的，才配当顶点。
> `Sub(G)` 是"对象的集合"而不是对象——没有任何映射连它，所以它是 **list**（面板里的表格），
> 不是 vertex。**但列表是入口不是终点**：面板里每一项都能「取出为对象」
> （编出一行 `闭包(G, r2, …)`，交给同一个求值器）。

两条正交编码（U5 起**形状被弱化**、强化"符号感"）：

- **形状 = 类型**：群 = **没有形状**（对象就是它的符号）/ 集合 = 圆 /
  作用 = 淡虚线框 / 映射 = 箭头 / **子群集不上画布**
- **颜色 = 来源**：蓝 = 用户声明 / 紫 = 运算产生 / 绿 = 作用

**节点不是卡片**——这条是 U5 由用户点出来的：

> "我们把对象放在圆角方框里面，里面甚至还放着 `|G| = 24` 这种信息……实际上的交换图呢？
> 只需要一个 S₄ 就好了。"

| 之前（v3–U4）| 现在（U5）|
|---|---|
| 圆角方框 + 描边 + 类型色底 | **没有形状**：只有符号 + 一小块淡底 |
| 副行 `\|G\| = 24` 画在节点里 | 副行**不上画布**，去信息面板看 |
| 字号 16，命中区 = 卡片 | 字号 18，命中区 = 符号本身（KaTeX 实测尺寸）|

留一块**淡底**是刻意的：纯裸符号在多条线穿过时会看不清（用户提的：*"如果没法看清可以给符号后面加一小块背景色"*），
而淡底还顺带承担了"颜色 = 来源"的编码。

**映射是"不占节点的对象"**（U3.1）：它在交换图上就是那支箭头，但**箭头本身可点选**——
点箭头就选中这个映射，悬浮球挂在箭头中点上方（§4.3）。

**类型改变是最强视觉信号**：`⟨S⟩` 把集合变成群，节点从**圆变方**，表示"结构升级"。
（`Z(G)` / `[G,G]` / `C_G` / `N_G` / `ker f` / `im f` / `⟨S⟩` 这类子群都升级为真群对象——用 core 的
`buildSubgroupGroup`，元素沿用母群对象、id 一致——所以 `Z(Z(G))` 是合法的。**U0 已落地**。）

节点状态：算中 / 已算 / 出错。

## 3. 输入层

### 3.1 三种输入形态

| 形态 | 适用 | 例子 |
|---|---|---|
| **文本定义** | 群 / 集合 / 数值 | `G = D_4`、`P = pSub(G, 2)` |
| **对象编辑器** | **映射 / 作用** | 列出 G 的生成元，逐个填像 |
| **搭积木** | 集合构造 | 分面表格就地筛选（见 §6）|

映射与作用**无法用一行文本表达**——同态由生成元的像唯一决定（数学上也是唯一正确的做法）。

### 3.2 输入框：两块（名字 | 表达式）—— ✅ 已落地（U1；v3.1 起挂在下方输入球上）

```
        ┌ ✎ ┐                                  ← 正下方中央的深色悬浮球
        ┌──────┬───┬─────────────────────┬──────┐
        │ 名字  │ = │ 表达式                │ 添加  │
        │(可空) │   │                     │      │
        └──────┴───┴─────────────────────┴──────┘
          B        {x ∈ A_4 : ord(x) = 2}
         名字留空 → 自动命名「B」（已避开注册表的 83 个调用名）
```

- **名字栏留空 → 自动命名**：`A, B, D, F, I, …`（即 `A, B, C, …, Z, A₁, B₁, …` 去掉被占用的）。
  名字栏的 `placeholder` 直接显示**将分配的那个名字**——"留空"不是盲盒。
- **自动命名必须避开三类名字**，否则会静默遮蔽功能。名单由注册表自动导出（`gal/naming.ts`），**不手写**：
  1. 已用过的对象名（大小写不敏感）
  2. **注册表的所有调用名**（83 个：`z` / `c` / `sub` / `ord` / `ker` / `closure` …）——
     否则自动生成 `Z = …` 会把 `Z(G)` 这个操作名遮掉，而这是**静默**的
  3. 保留单字母 `e`（单位元）· `p`（素数）· `G` / `H`（惯用群名，留给用户手写）
- **手写名字只拦两件事**：非法字符、与已有对象重名。命中操作名**只提醒不拦截**
  （`Z = Z(G)` 是用户的明确表达，系统不该管；但要让他知道自动命名会跳过它）。
- **表达式栏边打边校验**，复用求值器本身，所以"预览"和"提交后得到的"必然一致：
  - 合法 → `✓ [作用] 共轭作用(D₄) · |Ω| = 8`（类型 chip + 标签 + 副行）
  - 非法 → 红字 + core 的**定向提示**（可用写法清单）；「添加」同时置灰
- 名字提醒与表达式预览**并存两行**——手写 `sub` 这种名字时，提醒不该被预览挤掉。
- 兼容**整行粘贴**：名字栏空着、表达式栏贴 `G = D_4`，自动拆成名字与表达式
  （左半边不像名字的，如 `x^2 = e`，整体当表达式）。
- 快捷键：`Enter` 提交 · `Esc` 清空两栏并收起卡片。提交后**卡片保持开着**、输入清空——连续声明多个对象不用重新点球。

### 3.3 输入分层（同一个表达式栏，门槛从低到高）

| 门槛 | 方式 | 例子 |
|---|---|---|
| 零 | 目录点选 | 群目录手风琴（`getAllSmallGroups()`）|
| 零 | 记号 | `S_4` · `A_4` · `GL(2,3)` · `SmallGroup(16,13)` · `F21` |
| 低 | 构造 | `C_3 × C_2` · `G / N` · `A ∩ B` · `A \ B` · `A · B` · `⟨S⟩` |
| 低 | 生成元 | `⟨(123),(12)⟩`（母群未定，交记号解析）· `闭包(G, (123))`（在 G 里生成）|
| 编辑器 | 映射 | `映射(G, H, r→0, s→0)`（由构建器产出，也可手写）|

记号解析走 `parseGroupNotation`（本地优先：能本地建群就不退化到后端）。
**元素参数走 `resolveElement`**，接受 id / label / value / 循环记号——所以 `ord(S_4, (123))` 合法。

**关键设计**：对象与操作在输入层**同构**——都是"定义一行"。用户只需一套心智模型：**定义一行，画布上长一个东西。**

### 3.4 映射构建器 —— ✅ 已落地（U3）

**入口**：顶部多对象球（§4.4）里的「映射 f: G → H」→ 进 `pending` → 点源群 → 点靶群 → 弹构建器。

**为什么必须弹编辑器**：同态由**生成元的像**唯一决定。这不是产品偷懒，是数学本身——
`Z(G)` 可以一行写完，`f : D₄ → C₂` 却必须先说清 `r ↦ ?`、`s ↦ ?`。

**表单行为**：

| 元素 | 行为 |
|---|---|
| 生成元行 | 列出源群的生成元（`getGeneratorElements`），每行一个下拉选像（候选 = 靶群全部元素）|
| 实时校验 | 每改一项就走 `extendFromGenerators` + `verifyHomomorphism`：绿行给 `同态/嵌入/满射/同构 · \|ker\| · \|im\|`，红行给**定向报错**（`f(r·s) ≠ f(r)·f(s)`，并列出左右两端算出来的元素）|
| 自动填充 | 先问 `autoBuildMapping`（认得平凡 / 投影 / 商等）；认不出退回**平凡映射**（全映到单位元）——它必然良定义，当起点用 |
| 名字 | 留空走自动命名（与输入球同一套）|

**产出**：一行定义 `f = 映射(G, H, r→0, s→0)`，交给**同一个求值器**。
所以"点出来的映射"与"手写的映射"完全等价——用户看得见系统写了什么，也能改。

> 生成元的像有两种写法都对上：core 的生成元名（`r` / `s` / `a` / `s12`）与元素标签（`s` / `(12)` / `1`）。

## 4. 操作入口：三个入口 = 一张表

### 4.1 地基：`opsFor(selection)` —— ✅ 已落地（U0）

注册表（`apps/web/src/gal/ops.ts`）每条操作声明**命名参数 + 类型**：

```ts
type ParamType = 'group' | 'subset' | 'action' | 'map' | 'element' | 'prime' | 'int' | 'genImage'

interface OpParam { name: string; type: ParamType; optional?: boolean }
interface OpDef  { /* … */ params: OpParam[]; arity: number; optional?: number
                    variadic?: OpParam; editor?: boolean }
```

八个参数类型不是 `ValueType` 的复读——它回答的是**"用户选中画布上的什么，就能把这个参数填上"**：

| 类型 | 画布上能填 | 说明 |
|---|---|---|
| `group` | 群节点 | |
| `subset` | 圆节点（元素集 / 子群集）| 也接受群节点，见下 |
| `action` | **作用箭头**（点 `G ↷ Ω` 就选中它）| |
| `map` | **✗** | 映射不占节点——但它是**操作的产物**（U3 起），选中一个映射可做 `ker` / `im` |
| `element` | **✗ 标量** | 元素记号（`id` / `label` / **循环记号 `(123)`**），操作内部走 `resolveElement` |
| `prime` | **✗ 标量** | 素数 |
| `int` | **✗ 标量** | 整数 |
| `genImage` | **✗ 标量** | 生成元 → 像（`r2→e`），映射构建器或手写产出 |

两个 U3 才加的声明位：

- **`variadic`**（末尾可变参数）：`映射(G, H, r2→e, s→s)` 的像对个数不定，声明在 `params` 之外，
  不计入 `arity`，也因此**不影响 `opsFor` 的匹配**（不填也能选中）。
- **`editor: true`**：该操作凑齐对象参数后**不直接执行**，转交编辑器（§4.2 的 `editor` 档）。

**约定：标量参数只能排在参数表末尾。** `opsFor` 依赖这条做前缀匹配；模块加载时有断言，声明与 `arity + optional` 对不上会直接抛错。

`subset` 接不接受**群节点**，取决于本操作前面有没有群参数：

- 前面**没有**群参数（`∩` `∪` `\` `·`）——群总是可以当集合读，接受；
- 前面**有**群参数（`G/N`、`C_G(G,S)`）——要求它是其中某个的子群（`isSubgroupElementSet`）。
  否则"`A × B` 的 B"也会被当成集合，选中两个群就会冒出一堆多余的候选。

于是派生一个纯函数，**三个入口共用**：

```ts
opsFor(selection: GalValue[]): OpDef[]     // 按参数类型序列前缀匹配
```

三条规则：

1. 选中的值按顺序逐参匹配（前缀）；
2. 剩下的必需参数**必须是标量**——它们可以由用户在输入框里补，所以不算"还缺一个对象"；
3. 需要再选一个对象的，不出现：选中一个群时没有 `G × H`，得再选一个群。

| 选中 | 可做（节选，20 条 → 27 条）|
|---|---|
| 一个群 `A₄` | `Z` · `[G,G]` · `Aut` · `Sub` · `pSub` · `Syl` · `正规子群` · `共轭作用` · `正则作用` · `⟨G,…⟩` · `ord`（共 11 条）|
| 两个群 | `G×H` |
| 群 + 子群（可以是升级后的群对象）| `G/N` · `C_G` · `N_G` · 交/并/差/积集 |
| 一个作用 | `轨道` · `稳定子` · `不动点` |
| 一个集合 | `⟨S⟩` |
| 一个映射 | `ker` · `im` |
| 空 | 建群（记号 / 目录，不进 `opsFor`）|

**这解决了"操作别扭"**：入口原来是死的（一张长列表），操作是活的（随选中对象变），两者靠用户脑中对齐。补上参数类型后，对齐由系统做。

**U0 已落地的第一个入口**：左栏「可用操作」面板在选中画布对象后切成"可用于「X」· 可用 N 条"（可一键切回全部 27 条）。径向菜单（§4.3）与工具条（§4.4）是同一张表的另外两个前端，U2/U4 再接。

### 4.2 交互状态机 —— ✅ 已落地（U2；`editor` 档 U3 补）

```ts
type Interaction =
  | { kind: 'idle' }
  | { kind: 'selected'; target: string }                    // 单击对象 → 悬浮球 + 信息面板
  | { kind: 'menu'; target: string }                        // 悬浮球展开（实现里用 stage 表达两层）
  | { kind: 'pending'; opId: string; picked: string[] }     // 等**对象**参数（画布上接着点）
  | { kind: 'fill'; opId: string; picked: string[]; scalars: (string | null)[] }
                                                            // 对象参数已齐，等**标量**（顶部补参条）
  | { kind: 'editor'; opId: string; picked: string[] }      // 对象参数已齐，等**编辑器**（映射构建器）

type LayoutMode = 'auto' | 'manual'                          // U6 才用得上
```

```
idle ──click(node)──→ selected ──click(悬浮球)──→ menu（4 按钮）
menu ──click(「算」里的操作)──→ 执行 ──→ selected(新对象)
menu ──click(「造」里的操作)──→ pending(opId,[node])
pending ──click(node)──→ pending(opId, picked+[node]) ──凑够对象参数──→ 执行 / fill / editor
fill ──回车──→ 执行
editor ──确认──→ 产出一行定义 ──→ 执行（走同一个求值器）
pending / fill / editor ──Esc──→ idle
```

两档补充都是实践中补出来的：

- **`fill` 态**（U2）是原方案漏掉的一档。原文只写了"凑够 arity → 执行 或 editor"，
  但 `pSub(G, p)` / `Syl(G, p)` / `ord(G, g)` 这类操作的末尾参数是**标量**
  （素数 / 元素记号），画布上点不出来。所以补一档：对象参数凑齐后，顶部条换成
  "补参数"——素数给默认值 `2`、元素记号留空待填，回车执行。
- **`editor` 态**（U3）就是原方案里写了但一直没人用的那一档。`映射(G, H, …)` 对象参数凑齐后
  **不能直接执行**——生成元的像还没填。于是转交映射构建器（§3.4），由它产出定义行再回到求值器。

`editor` 态**点空白不关闭**：构建器里可能已经填了一半的像，误触丢掉比"点空白没反应"更烦人。
（`Esc` 与「取消」照常关闭。）

`pending` 的反馈**四条都要给**（实现里都有）：

| 反馈 | 实现 |
|---|---|
| 顶部提示条 | 「选择「N」（集合 / 子群）· 第 2 / 2 个对象」+ 已选参数 + `Esc 取消` |
| 十字光标 | 画布加 `.picking` |
| 已选节点高亮 | 换色描边 + 加粗 |
| **不可点的节点变暗** | 用 `opsFor` 同一套匹配规则筛出可点集，其余 `opacity: .26` |

最末一条是加出来的：只高亮"能点的"还不够，**点击失败的挫败感比高亮带来的便利更大**。

执行走的是**同一条求值路径**：点选出来的操作先被**编回一行文本**（`gal/compose.ts`），
再交给 `evalExpr`——所以"点出来的"和"打出来的"行为必然一致，而且**用户看得见系统替他写了什么**
（左栏里真的多出一行，可读可改）。同名同标签的重复计算会被去重，直接选中已有对象而不再加行。

### 4.3 对象旁边的入口：悬浮球 —— ✅ 已落地（v3 改版）

> **v3 改版**：U2 那版"三类两层径向菜单"（看 / 算 / 造）已经换掉。下面是现行设计。

选中对象后，**节点左上角**出现一颗**深色悬浮球**（`⋯`），点开环绕按钮。
**环绕的构成按值类型定**：

**① 群**（4 个按钮）：

| 按钮 | 行为 |
|---|---|
| **基本** | 打开信息面板（§5），切到「基本」tab |
| **元素** | 同上，切「元素」（元素表格）|
| **子群** | 同上，切「子群」|
| **操作** | 展开下拉面板，列出**全部单对象操作**——点哪个就**立刻创建对象**，不用再选参数 |

**② 其它值**（映射 / 集合 / 作用…）：一个「信息」+ **直接铺出来的单对象操作**。
单对象操作 ≤ 3 条时不收进下拉，直接当按钮环绕——**映射的 `ker` / `im` 因此一步可点**：

```
        点箭头 →  ⋯  →  [信息] [ker] [im]   ← 点 ker 立刻长出 ker(f)
```

这条是 U3.1 用户提的："点击箭头然后点击 ker 按钮，比输入 `K = ker(F)` 方便"。
配套的实现是：**箭头带 `objectId`**（`GalEdge.objectId`）→ 可点选；**箭头上报中点锚点**（`NodeAnchor.kind = 'edge'`）
→ 球知道该浮在哪。结构伴生箭头（π / π₁ / ↪）还不是对象，因此不可点。

改版的三条理由：

1. **少一层点击**。原来"看"是**一类**，点开才出 7 个只读项；现在拆成 3 个直接入口，且与信息面板的 3 个 tab 一一对应——点了就看见，不用二段展开。
2. **"算 / 造"的二分取消**。单对象操作留在球里（点一下就完事）；**多对象操作搬到显示区正上方另一颗球**（§4.4）——因为"多对象"本来就不依赖"你选中了谁"，挂在节点上是错的位置。
3. **位置与颜色**。挂**左上角**：右侧和下方是交换图出边的地方，左上角空着。做成**深色**：画布是浅色，深色球是"这里可以点"的最强信号；环绕出去的卫星按钮保持浅色胶囊（它们是"选项"，不是"入口"）。

**环绕角度只铺在「上半圈 + 左侧」（-180° → 0°）。** 球在节点左上角，节点在球的**右下**方向——
按整圈均分的话，正下方那颗会结结实实压住节点标签。环绕半径也随节点尺寸放大（`max(54, r + 22)`）。

> **单对象操作 = `singleOpsFor(v)`**：`opsFor([v])` 里 `objectArity ≤ 1` 的那些，**再排除产数值的**
> （`ord` 这类）——用户定了"计算先不弄"。
>
> **多对象操作 = `multiOps()`**：**不能**用 `opsFor` 筛。`opsFor` 的语义是"选中的值能把参数填满"，
> 而"多对象操作"恰恰是"参数还没填满"的那些，用 `opsFor` 筛必然为空。
> （U2 就是栽在这儿：菜单里的「造」类恒空。真浏览器走查才抓到。）

## 6. 集合构造器

`{x ∈ A₄ : x² = e}` 这类集合，有两条前端，**编译成同一个 AST**：

```
文本定义  B = {x ∈ A₄ : ord(x) = 2}  ┐
                                      ├─→ FilterSpec ─→ 筛(枚举(域,类型), 谓词) ─→ subset 对象
点击构造  元素表 → 点「阶」列 → 选 2  ┘        ↑
                                      （点击流把等价文本回填到输入框）
```

```ts
interface FilterSpec {
  domain: Ref
  from: 'elements' | 'subgroups'
  pred: AttrPred | WordPred
  combine?: { op: '∧' | '∨'; right: AttrPred | WordPred }
}
interface AttrPred { kind: 'attr'; attr: AttrName; op: '=' | '|' | '∈'; value: unknown }
interface WordPred { kind: 'word'; lhs: string; rhs: string; vars: string[] }   // 例 x^2 = e
```

**两条前端不是竞争关系。** 点击流**顺手把等价文本写出来**——不用二选一，点击流替你写出那行文本，下次你就能直接打。用户是"看着语法被写出来"学会的，这是这个功能的真正教学价值。

### 6.1 分面表格（不是向导）

`元素列表 → 属性 → 阶 → 2 → 固化` 如果做成向导，有两个毛病：**一次性的**（生成后选择状态丢失，改成 3 要从零重来）、**不可见的**（5 步才看到东西）。

修法：竖卡的列表做成**带分面的表格**——列头可点、就地筛选、可撤销：

```
┌ 元素表 ──────────────────────────────────────┐
│ 元素    阶▾    ∈Z?    共轭类   中心化子        │  ← 列头可点 = 分面
│ e       1      ✓      1        A₄            │
│ (12)    2      ✗      2        C₂×C₂         │
│ (123)   3      ✗      4        C₃            │
├──────────────────────────────────────────────┤
│ 筛选：阶 = 2 · 3 个元素                       │  ← 实时
│ = {x ∈ A₄ : ord(x) = 2}            [固化 → B] │  ← 实时生成的表达式
└──────────────────────────────────────────────┘
```

**关键：筛选状态不是 UI 状态，它是对象表里的一行。**
于是"可再编辑"是**免费**的——点画布上的 `B` → 竖卡回到筛选态、`2` 还亮着 → 改成 `3` → 整图自动重派生（"对象表 = lines 的纯函数"天然支持）。

### 6.2 「类型 × 属性」表的第二重身份

[ARCHITECTURE.md](ARCHITECTURE.md) §4 那张表原本只是"筛的谓词库"，它**同时是分面表格的列定义**：

| 对象 | 分面列 |
|---|---|
| 元素 | 阶 · ∈Z? · 共轭类 · 中心化子 |
| 子群 | 阶 · 指数 · 正规? · 极大? · Sylow? |
| 群 | 阶 · 交换? · 循环? · 单? · 可解? · 幂零? |

**一处定义，两处消费（筛选 + 展示）；列随选中对象类型自动变。** 所以同一个机制既能造 `{x : 阶=2}`，也能造 `{H : 正规}`。

### 6.3 属性谓词 vs 字谓词

| | 例 | 有列可点吗 | 实现 |
|---|---|---|---|
| **属性谓词** | `阶 = 2` · `正规` · `属于中心` | 有（分面下拉，可补全）| core 属性 + 枚举筛选 |
| **字谓词** | `x² = e` · `xy = yx` · `[x,y] = e` | 无（只能打字）| `parseWord(text, gens)` → 代入 `group.multiply` 折叠 → 比 `identity`；`parseRelationEquation` 校验 `f=e` / `f₁=f₂` 形式 |

两者用 `∧ ∨` 组合（即 ARCHITECTURE §4 的"写死 + 少量组合"），**不开放任意表达式**（不写 lambda）。

**属性谓词可自动翻译成字谓词**：`阶 = 2 ⇔ x² = e`。这不是冗余——**这正是证明里"为什么等价"的那一步**。

### 6.4 固化出的对象

固化结果是一个 **subset 对象**：画布上一个**圆** + 颜色（对齐 GroupViz 的 `{label, color, isSubgroup, isNormalSubgroup, type}` + `SUBSET_COLORS`）。

**若它恰好是子群，系统给提示但绝不自动改类型**：

> 这其实是个子群（V₄），要不要升级成群对象？

**对象类型是用户的心智模型，系统悄悄改会造成"这到底是集合还是群"的混乱**；但升级入口必须在手边（一次点击，不藏进菜单）。
升级用 `subgroupFromElementIds` 校验、`subgroupStructureSymbol` 命名、`buildSubgroupGroup` 造群。

## 7. 操作的构成与画布的边

### 7.1 操作 = 结果对象 + 结构伴生 —— ✅ 已落地（U3）

群论操作很少只"吐一个结果"，通常还伴生一个结构关系：

| 操作 | 结果对象 | 伴生结构 | 落地（`derive.ts` 的 `alongsideEdges`）|
|---|---|---|---|
| `G / N` | 商群 Q | 投影 `π : G → Q` | ✅ 边 `G →(π) Q` |
| `G × H` | 积群 | 两个投影 | ✅ 边 `P →(π₁) A`、`P →(π₂) B` |
| `Z(G)` · `[G,G]` · `C_G` · `N_G` · `⟨S⟩` | 子群（真群对象）| 包含 `H ↪ G` | ✅ 边 `H →(↪) G` |
| `ker f` · `im f` | 子群（真群对象）| 包含 `ker ↪ dom`、`im ↪ cod` | ✅ 母群从**映射的端群**取 |
| `共轭作用(G)` · `正则作用(G)` | 作用（edge）| 作用线 `G ↷ Ω`，Ω = G 自身 → **自环** | ✅ 边 `G →(↷) G` |
| `共轭作用在(G, Ω)` | 作用（edge）| 作用线 `G ↷ Ω` | ✅ 边 `G →(↷) Ω`；Ω 由 derive 找 / 造 |
| `轨道(A, x)` | 集合（Ω 的子集）| 包含 `Orb ↪ Ω`（等于 Ω 时写 `=`）| ✅ |
| `稳定子(A, x)` | 群（G 的子群）| 包含 `Stab ↪ G` | ✅ 母群从**作用的群**取 |

**这些伴生结构就是交换图上箭头的真正来源。交换图不是用户手画的，是操作长出来的。**

两条实现约定：

- **伴生箭头是一等公民（实线）**，所以有伴生箭头的对象**不再画来源线**——
  否则同一对节点上会叠一条反向的虚线（`Z(G)` 既画 `Z ↪ G` 又画 `G ⇢ Z`，图立刻乱）。
- 母群怎么找：结果群的来源里有群对象就用它；来源是**映射**（`ker` / `im`）就用映射的端群。

**显式映射对象**（U3）另画一条实线箭头 `domain → codomain`，标签是映射的对象名（`f`）。

> **尚未接入**：core 的 `naturalProjectionMapping` / `subgroupInclusionMapping` /
> `directProductProjectionMapping` 三个**映射表生成器**。当前伴生只画边（边只需要 from/to），
> 不需要映射表；等"对 π 本身做 `ker` / `im`"这类需求出现时再补——那时边要升级成**真正的映射对象**。

### 7.2 第一同构定理：给出 φ，剩下两条自己长出来 —— ✅ 已落地（U5）

用户的原话：**"真正的第一同构定理的交换图只有 S₄、S₃、S₄/ker(φ) 和三条线。
当我们给出 phi 这条线后，剩下两条能立马生成。"**

```
        G ──── φ ────▶ H
        │              ▲
        π              ≅
        ▼              │
      G/ker φ ─────────┘
```

实现（`gal/build.ts` 的 `firstIsoObjects` + `gal/derive.ts` 的 `firstIso` 分支）：

- 用户写下 `φ = 映射(G, H, …)`（一条线）后，工具**补出第三个顶点** `G/ker φ`：
  取 φ 的核，`computeQuotientGroup` 造商群，作为**隐式对象**追加
  （`id = "φ/ker"`、`opId = 'firstIso'`）。
- `derive` 为它补两条边：`G →(π) G/ker φ` 与 `G/ker φ →(≅) im φ`
  （满射时 `im φ = H`，直接连到靶群）。

**隐式对象的三条规矩**：

1. **上画布、可点选**（点它 → 信息面板给同构识别结论，如 `C₆/N ≅ C₃`）；
2. **不占定义行**、不出现在对象/操作清单——它是 φ 的伴生，删 φ 即消失；
3. **退化情形不生成**：核平凡（商群 ≅ G）或核 = 全群（商群平凡）都不画；
   **用户自己建了 `K = ker(φ)` 时也不补**——他正在手动走这条路，替他把顶点补上只会出现两个等价的群。

> "核应该是画布上可有可无的东西"——对：用户不写 `ker(φ)`，它就不作为节点出现，
> 而是被折进 `G/ker φ` 这个顶点里；写了，它就是个普通节点。

### 7.3 三种边

| 边 | 样式 | 含义 | 参与交换图？ |
|---|---|---|---|
| **map** | 实线箭头（2.4 宽）+ 标签，**可点选**（点中变橙加粗）| 数学中的映射（一等对象）| 是 |
| **action** | 绿色实线 + `↷` | 群作用 | 是 |
| **provenance** | 淡虚线 | "该节点由某操作算出"（辅助）| 否 |

**同一类 `map` 里还要再分两级**（用户那张 S₄→S₃ 的图证明有必要——全黑实线挤在一起看不出主次）：

| 边 | 颜色 | 宽 | 含义 |
|---|---|---|---|
| **显式映射对象**（带 `objectId`）| 深黑 | 2.4 | 用户造的映射，交换图的主角 |
| **结构伴生**（π / π₁ / ↪ / `=` / `≅`）| 蓝灰 | 1.7 | 操作派生出来的结构关系，配角 |
| **作用**（`↷`，带 `objectId`）| 绿 `#0F6E56` | 2.2 | 一等边，**可点选** |

来源线**默认显示，可全局关闭**。SVG 上分别带 `gedge-map` / `gedge-action` / `gedge-provenance` 类名。

**自环**（`G ↷ G`，如共轭作用 / 正则作用）单独画一条弧线——两端重合时"从节点边界出发的直线"没有意义。

**`Orb` 的边**：轨道是 Ω 的子集 → `Orb ↪ Ω`；轨道长度等于 Ω 时标签写 **`=`** ——
那就是「作用传递」，也正是 Sylow II 的结论。**`Stab` 的边**：`Stab ↪ G`（稳定子 = `N_G(H)` 是 G 的子群）。

**点选命中区**：实线只有 2.4 宽，直接点很难中——所以每条可点选的边额外叠一条
`strokeWidth: 14` 的透明命中线（`.gedge-hit`）。

### 7.3b 箭头**形状**编码映射类型 —— ✅ 已落地（2026-09-19）

`GalEdge.arrow` 由映射属性推出（`derive.ts` 的 `arrowOf()`，判不出时**不猜**），渲染成 marker
（见 DIAGRAM_SPEC §1.6）：

| `arrow` | 形状 | 画法 |
|---|---|---|
| `surjective` | **双箭头** `↠` | `marker-end` = `-surj`（两个 V 叠放，都朝终点）|
| `injective` | **尾部钩子** `↪` | `marker-start` = `-hook`（起点处一条竖钩）|
| `iso` | **双向箭头**（同构 = 双射）| `marker-end` 与 `marker-start` **都** = `-head`，两端各一个尖 |
| （无）| 普通箭头 | `-head` |

结构伴生箭头按**数学身份**给形状：`π` / `π₁` / `π₂` 是满射、`↪` 是单射、
第一同构的 `≅` 与轨道的 `=`（相等）都是同构 → **双向**。于是 `G ↠ G/N`、`im φ ↪ H`、
`G/ker φ ≅ im φ` 一眼可分——**形状本身就在讲定理的三个断言**（满 / 单 / 双）。

marker 按**视觉族**（`prov` / `action` / `alongside` / `map`）成套生成——从前颜色写死在定义里，
于是蓝灰的伴生边配了个深色箭头。

边标签加了**白色描边 halo**（`paint-order: stroke`）——不然线从字上穿过去，`π` / `↪` 根本读不出来。
标签字号 = 两端对象字号的**较小者 × 0.68**（比对象小一号），位置在**沿行进方向的左侧**：
屏幕坐标下"方向 `(dx,dy)` 的左侧" = 法向 `(dy, −dx)`，沿箭头方向走 **30%** 处再让开 9
——30% 而非中点，是因为多条箭头汇聚到同一节点时中点会糊成一团。

## 8. 布局

### 8.1 规则

**课本级交换图的第一判据是"水平箭头同高、垂直箭头同列"**（DIAGRAM_SPEC §1.2），
所以布局是**硬约束网格**，不是"尽量对齐"：

1. **行 = 派生层**（`level = 依赖链长度`）：同层 y **严格相等**，行高 = 该行最高节点
2. **列 = 竖直约束的连通分量**：
   - `π` / `π₁` / `π₂`（投影）、`↪`（包含）、**`=`（轨道 = Ω，即"传递"）** 与
     **`↷`（作用）** 在课本里都是**竖直线** → 两端强制**同列**
     （`=` 是 2026-09-19 补进来的：漏了它，Sylow III 的 `Orb = Ω` 会横着跑，三层结构散掉）
   - 用户造的映射是**水平**的、`≅` 是**对角**的、来源线是辅助 → 都**不**参与列合并
   - **合并用贪心**（短跨度优先）；合法性判据是**合并之后整组**的全局检查
     ——组里**任何一条**竖直约束边的两端之间都不许夹着别的成员，否则那条边的箭头会从
     中间那个对象身上穿过去。（2026-09-19 升级：从前只看**当前这条边**的 level 区间，
     漏了"合并之后新产生的同列关系"。第三同构真图里 `K ↪ G` 与 `G ↠ G/N` 单看各自都干净，
     但把 `K` 合进 `G` 那一组后，`G ↠ G/N` 就跨过了 `⟨r²⟩`。）
   - **`π` 优先于 `↪`**：`π`/`π₁`/`π₂`/`=` 是课本最硬的站位规范（商映射只能竖直画），
     `↪` 是软的（包含箭头斜着画完全正常）。冲突时 π 先占列，`↪` 自己变斜线。
   - **同层的边不参与列合并**：同层就是要画成水平箭头的（`N ↪ K` 是第三同构矩形的上边），
     把它当竖直约束只会把不相干的节点拉进同一组、挤出一堆空列。
   - 一列里两个节点撞在同一行时，后者右移到最近的空列
3. **列宽 = 该列最宽节点**（先算出**理想位置**），最后一步把行列中心**量化到规则网格**：
   列间距因此变成**等距**——顺手解决了 DIAGRAM_SPEC §2.2 那条"节点宽度参与布局"（列宽参差）
4. 节点尺寸由**标签 KaTeX 实测**决定，整体**统一缩放**（连字号一起缩放）
5. **行内相邻约束（2026-09-19）**：同层的**显式映射边**（用户画的 `φ : G → H`）两端之间
   **不许夹别的列组**——夹着的组整体挪到该行末尾，迭代至稳定。
   这是"箭头不该从对象身上穿过去"在**水平方向**的对应物（竖直方向由第 2 条的
   全局穿行判据保证）。真截图抓到的场景：画布上同时有 `C₆ ──φ──▶ C₃` 与另一个
   无关的输入对象 `D₄`，两者同层，`D₄` 落在 φ 的两端之间 → 箭头从它身上穿过去。
   （判据仍是**边的语义**：只有带 `objectId` 的映射算水平关系，`π` / `↪` / `↷` 竖直、`≅` 对角。）
6. **不上画布的对象不占行（2026-09-19）**：`level` 只按**画布顶点**（群 / 集合）算——
   映射、作用、子群集、数值都是"关系"或"表格"，它们对自己下游顶点的层级贡献**不加一**。
   否则图里会出现**空行**：第一同构定理的正方形会摊成三行（`G`、`H` 一行 ‖ 空一行 ‖
   商群与像一行），而课本里它是两行。

> **判据必须按"边的语义"来，不能按几何猜。** 第一版用"竖直倾向（`dy ≥ dx`）"合并列，
> 结果 `≅` 这条对角边把 `C₆`、`C₃`、`C₆/ker φ` 传染成一列——`C₆` 与 `C₃` 直接叠在一起。
> 改成"只有 `π` / `π₁` / `π₂` / `↪` 才约束同列"之后，第一同构定理自动排成课本的样子：
> `C₆ ──φ──▶ C₃` 水平、`C₆ ──π──▶ C₆/ker φ` 垂直、`≅` 对角。

引擎：`@groupviz/core` 的 `computeLatticeLayout(nodes, edges, opts)` 只用来出**初值**（定行列的相对次序），最终坐标由上面的网格重算；拥挤时用其 **LOD 三档**（`full` 名片 → `compact` 胶囊 → `dots` 点）。

### 8.2 格点 · 视图 · 手动布局 —— ✅ 已落地（2026-09-19，U10）

**格点是一条无限延伸的规则网格**，而且**画出来了**。§8.1 的"对象落在格点上"不是抽象约束：
网格有原点与固定步长，像坐标纸一样**铺满整个画布**（pan / zoom 到多远都有格点，
按视口现算），画布上就是那些淡灰小点（`.grid-dot`）。两条路径都保证落在格点上：

| 路径 | 怎么保证 |
|---|---|
| **自动布局** | 算出的行列中心**量化到最近的网格线**（步长取"相邻间距的中位数"，量化顺带把不均匀的列宽差**拉平成等距**）|
| **手动拖动** | 松手**吸附到最近的空格点**，跳过已被别的节点占住的格点 |

用户因此**看得见**对象能停在哪、也能停到哪——而不是只有系统自己知道。

**视图可以缩放平移**（三个入口，互不冲突）：

| 操作 | 效果 |
|---|---|
| 滚轮 | 围绕**指针**缩放（指针底下的世界点保持不动），范围 15%–600% |
| 空白处拖动 | 平移画布（pan） |
| 双击空白 / 工具条「适应窗口」 | 回到自动 fit（读数 100%）|

右下角工具条常驻显示**当前缩放百分比**。视图的归属是"**用户一旦动手就归他管**"：
`userView = null` = 跟随自动 fit（加一行会自动重排并居中）；一旦 pan / zoom 过，
视图就不再被内容变化打断。

**节点可以拖**（决策 ④ 落地）：

- **拖 = 钉住**：拖过的节点记下世界坐标；布局**照常算**（它仍占着自己原来的行列），
  最后一步才覆盖它的坐标 → **拖走一个节点不会引起别的节点重排**
- **吸附到最近的空格点**：松手时按"列最近 × 行最近"吸附，并**跳过已被别的节点占住的格点**
  （否则一拖就叠在一起）；拖动过程中显示**吸附预览环**，提前告知会落在哪
- **自动改边**：边每帧从节点坐标派生，节点一动边就跟着重画（`φ` / `π` / `↪` / `=` 都实时更新）
- **一键恢复自动**：工具条「恢复自动布局 · n」（n = 被钉住的数量），清空全部钉住
- **持久化**：钉住位置按对象 id 存 localStorage；`?empty=1` 的空画布模式**不读也不写**
  （免得走查脚本之间互相污染）

**实现上的两个坑**（都靠真浏览器走查抓出来，不是推理出来的）：

1. **指针监听不能靠 `setPointerCapture`**：在 React 合成事件里它只让**第一次** `pointermove` 到位，
   平移量因此只有应到的 **1/8**（拖 90px 只动了 11px）。改成 `pointerdown` 时把
   `pointermove` / `pointerup` 挂到 **window** 上——指针移出画布、移到浮层上都能继续拖。
2. **包围盒必须用"自动布局"的位置算**，**不能**把被钉住 / 正在拖的节点算进去：
   否则拖走一个节点 → 包围盒一变 → 整张图跟着重新缩放 → 松手瞬间所有东西都跳一下，
   而且**落点不再是格点**（走查里直接抓到这一条）。

> 浮层会吃掉指针事件：左上抽屉 / 左下数值 / 右下工具条 / 输入球上按下都**不会** pan ——
> 这是对的（那是面板的领地），所以"在哪按下"决定是 pan 还是操作面板。

**与 GeoGebra 的关键区别**：Galculator 的节点位置是**结构分层**，不是数值坐标。
拖拽是"人为选择的表达"，**不改变数学**。

## 9. 数值区（上拉抽屉）—— ✅ 已落地（v3 改版）

- **位置**：**左下角**的上拉抽屉（不再在左栏里）
- **只放两种东西**（用户定的口子）：

| 来源 | 怎么进来 |
|---|---|
| **拖动收集** | 在别的面板看到的数字（元素表的「阶」、子群列表的「|H|」…）直接拖进来。dragstart 写 `application/x-gal-number` 载荷，drop 时读；**整块面板体就是投放区**（拖到上方有虚线高亮反馈）|
| **用户计算** | `n = ord(G, r2)` 这类主动算出来的数值 |

- **两者在数据上是同一件事**（一个标签 + 一个数），只是来源标一下、键前缀不同（`d:` / `c:`）
- **语义**：证明过程中的临时量，算完即弃（栈式）
- **分工原则**：结构化对象上画布；纯数值进数值区

> **尚未做**：点数值行把它插回输入框参与后续运算；数值区内的手动算式求值（用户已定"计算先不弄"）。

## 10. 节点浓缩

节点过多时允许浓缩，但**必须分两类、视觉上区分**：

| | 数学浓缩 | 视觉折叠 |
|---|---|---|
| 含义 | 有确定的数学内容 | 无数学含义，纯收纳 |
| 视觉 | **复合节点**（内部可见结构）| **分组框**（仅收起）|
| 例子 | 商 `G/N`（N 的每个陪集压成一点）、共轭轨道浓缩 | 步骤过多，收起已完成的一段 |

**绝不能混为一谈**——否则用户会误以为折叠的节点有代数含义。

**数学浓缩已有先例**：GroupViz `Group` 类型带 `cosetMemberLabels` / `cosetInternalEdges` / `cosetInternalLayout`，用于商群节点内部渲染正规子群的 Cayley 图；`mergeLatticeByConjugacy` 把子群格按共轭轨道压成轨道格。**直接复用。**

## 11. 画布图（CanvasGraph）

画布图是那块**背景板**：承载节点与边，布局引擎在它上面排位。
**由对象表派生，不是手画的**（与实现对齐，见 `apps/web/src/gal/`）：

```ts
// value.ts
type ValueType = 'group' | 'elements' | 'subgroups' | 'map' | 'action' | 'number'

// types.ts
interface GalObject {
  id: string                       // 对象名
  origin: 'input' | 'derived'      // 颜色来源
  label: string                    // 主行
  sub?: string                     // 副行
  def: string                      // 原始定义（等号右侧）
  sources: string[]                // 来源线目标（由参数链自动收集）
  value: GalValue                  // 6 类值之一
  opId?: string                    // 命中的注册表 id
  recipe?: string                  // 配方（解释用元数据）
  note?: string
}
interface CanvasNode extends GalObject { shape: 'group' | 'set' | 'action'; level: number }
interface GalEdge { id: string; kind: 'map' | 'action' | 'provenance'; from: string; to: string
                   label?: string; objectId?: string }   // objectId = 背后的对象（映射箭头），可点选
interface CanvasGraph { nodes: CanvasNode[]; edges: GalEdge[] }
```

**派生规则**（三条，均已落地）：

1. 每个对象 → 一个节点（`number` 除外，它进数值区；`map` **不占节点、只画边**，但箭头可点选）
2. 每个操作的源 → 一条来源线（`sources` 由参数链自动收集，不是每个操作手写）；
   **若该对象已带结构伴生箭头（§7.1），则跳过它的来源线**（避免反向叠线）
3. 操作若带**结构伴生**（§7.1）或对象本身是映射 → 生成 `map` 边；
   作用节点与其源群之间生成 `action` 边

> U3 起 `map` 有了生产者：**映射构建器**产出 `映射(G, H, r→…, s→…)`，
> 于是 `ker` / `im`（U0 就注册好、一直闲置）自动可用——它们选中一个映射就能跑。

- **信息面板还缺两个分区**：**陪集分解**（`buildCosetViewData` 已备，要设计陪集条的展示）、

- **顶部完整工具条**（群目录 / 积 / 商 / 作用 / 操作表 / 布局开关）未做，目前只有多对象球（§4.4）；

### 13.3 KaTeX 的适用范围 —— ✅ 两处都走 KaTeX（U4 改）

**v3 那版是"面板走 KaTeX、画布用 Unicode 近似"**，理由是画布那三条难点
（SVG 里塞 HTML / 尺寸要回量 / 标签是混合语义串）。
用户看过实物后的评价是"**没看到 tex 渲染**"——三条难点这轮全解决了：

| 难点 | 解法 |
|---|---|
| SVG 里塞 HTML | 节点标签改走 `<foreignObject>`（Chromium / Firefox / Safari 都支持）|
| 尺寸要回量 | 改**离屏测量**（`ui/Tex.tsx` 的 `measureTex`）：离屏容器里渲染后量一次，按 `标签@字号` 缓存。比原来的字符宽度估算**更准**，也不需要"渲染后重排" |
| 标签不是 TeX 源 | 新增 `gal/tex.ts` 的 `toTex()`：把 Unicode 展示串**反推**成 LaTeX |

`toTex` 的转换顺序（顺序本身是知识）：**上下标 → 运算符/希腊字母 → 函数名 → 中文**。

- 上下标：`₀-₉` / `ₐₑ…` → `_{}`；`⁰-⁹` → `^{}`
- 运算符：`∩ ∪ × · ∘ → ↦ ↪ ≅ ⊴ ⊆ ⊂ ∈ ⟨⟩ ∖` → `\cap \cup \times \cdot \circ \to \mapsto \hookrightarrow \cong \trianglelefteq \subseteq \subset \in \langle \rangle \setminus`
- **函数名**要包 `\operatorname{}`：不包的话 `Sub` 会被排成 `S·u·b`——那在数学里是乘积的意思
- **中文**要包 `\text{}`：math mode 下的 CJK 渲染失败（`9 个子群` → `9 \text{个子群}`）

`ui/Tex.tsx` 三条路：`<Tex>` 强制按 TeX 渲染；`<TexOrText>` 先过 `toTex` 再渲染
（`shouldTex` 只用来挡**纯 ASCII 名字**——`A` 走 KaTeX 与纯文本视觉差别很小，省一次排版）；
`labelTexHtml` / `measureTex` 供画布用（都带缓存）。

> **走查脚本注意**：画布节点标签不再在 `<text>` 里了——KaTeX 的 DOM 里 `S₄` 的 `textContent`
> 是 `S4`（数字是独立 span）。定位统一走 `<g class="gnode" data-label="S₄">` 上的 **`data-label`**。
