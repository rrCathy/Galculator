## 交互模型草案（本轮产出，待用户拍板）
- 核心主张：**画布 = 交换图**（对象=节点，操作=箭头，位置由"关系"决定）；对照 Desmos 的画布=坐标系（对象=曲线，位置由数学决定）。背景是交换图版面（淡点阵吸附网格），不是坐标网格。
- ① 对象输入：左栏「名字 = 定义」，与 Desmos 表达式列表同构；分层输入（记号 S_4 / 构造 C_3×C_2 / 生成元 ⟨(123),(12)⟩ / 目录点选）。
- ② 操作输入：**与对象同构，也是「名字 = 定义」，只是引用已有对象**（f : G→H 是一行；K = ker(f) 是一行）。统一心智：定义一行，画布长一个东西。
- ③ 对象展示：节点卡（主行符号 + 副行阶 + 状态点），悬停展开详情，点击高亮关联操作。蓝色=输入对象，紫色=运算产生的对象。
- ④ 操作展示三分类：映射→带标签箭头；运算(ker/商/中心)→派生边+新节点；群作用 G↷Ω→特殊作用线。
- ⑤ 摆放：分层布局（Sugiyama/DAG）——映射方向决定层（f:A→B，B 在 A 右侧/下方）、同层对齐、箭头正交、网格吸附。位置建议"自动为主+手动微调"。
- ⑥ 我补的第六问（用户没问但关键）：**数值计算不上画布**（C(12,4)=495、|O|=3），进"演算带"（画布下方横向步骤流）或节点旁气泡。

## 用户四点回应 + 操作类型学修正（22:49）
- 用户拍板：①位置：**混合** ✓；②操作三分类"考虑得少"，点名两个反例——**集合运算**怎么表示、**群衍生出 Aut(G)** 怎么表示；③数值：**左侧栏新建"数值区（栈）"**（不是画布下方演算带）；④节点太多：**必要时多节点浓缩为一个节点，但浓缩在特殊情况下有特殊数学含义**。
- **核心修正**：原三分类（映射/运算/作用）是按"视觉"分的，不够——应**按数学结构分**。新框架：
  - **操作 = 结果对象 + 结构伴生**。伴生结构（映射/作用/包含）**就是交换图箭头的真正来源**（如 G/N 伴生 π: G→G/N；Aut(G) 伴生作用 Aut(G)↷G；A∩B 伴生包含 A∩B↪A）。
  - **画布两种边**：①映射边（实线箭头，一等对象）②来源线（淡虚线，"由该操作算出"的辅助信息）。
  - **形状分类型 + 颜色分来源**：圆角矩形=群，圆形=集合，箭头=映射；蓝=输入，紫=运算结果。
- 集合运算 → 集合与群同级（圆节点），交/并/积是二元汇聚；**⟨S⟩ 是类型改变（集→群，节点形状圆变方）**，最强调视觉信号。
- Aut(G) → 一元导出，产出群节点 + 自动伴生作用线；揭示"衍生往往产出 对象+关系 对"。
- 数值区（栈）：左侧栏分三区 对象/操作/数值；数值按计算顺序累积，可点击插回输入。
- **浓缩两分**：数学浓缩（商=把 N 陪集压成一点、轨道浓缩，有确定含义，是"复合节点"，内部有结构）vs 视觉折叠（纯收纳，无数学含义）。GroupViz 已有先例：Group 类型的 cosetMemberLabels/cosetInternalEdges/cosetInternalLayout（商群节点内部渲染正规子群 Cayley 图）。
