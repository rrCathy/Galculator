> 并列文档：[ARCHITECTURE.md](ARCHITECTURE.md)（内核架构：值类型 / 10 原语 / 操作清单）· [PROOF_SPEC.md](PROOF_SPEC.md)（证明层）· [ROADMAP.md](ROADMAP.md)（U0–U7 / M0–M4）。

## 0. 一句话

**用户应该在对象旁边完成他想要的操作。**

这是与 Desmos 最大的区别：Desmos 的画布是**输出**（你打字它画图）；Galculator 的画布是**操作台**（你在图上点对象、在它旁边选操作）。交换图本身可交互，是这个产品的身份。

## 1. 核心主张：画布 = 交换图

| | Desmos / GeoGebra | Galculator |
|---|---|---|
| 画布是什么 | 坐标系 | **交换图**（有向图）|
| 对象是什么 | 曲线 | **节点**（群 / 集合 / 作用）|
| 位置由什么定 | 数学（f 的取值）| **关系**（映射方向 / 派生深度）|
| 背景是什么 | 坐标网格 | 交换图版面（淡点阵，仅用于吸附）|
| 画布角色 | 输出 | **操作台** |

**用户不是在画图，是在"长"一张交换图。**

## 2. 一级对象与视觉编码

对象与内核的**值类型**一一对应（定义见 `apps/web/src/gal/value.ts`）：

| 值类型 | 形状 | 颜色 | 例子 |
|---|---|---|---|
| `group` | 圆角矩形（**方**）| 蓝=输入 / 紫=运算 | `D_4`、`G/N`、`Aut(G)`、**`Z(G)`**、`⟨S⟩` |
| `elements` | 圆形 | 同上 | 共轭类、轨道、`A ∩ B`、`A · B` |
| `subgroups` | 圆形 | 同上 | `Sub(G)`、`pSub(G,2)`、`Syl(G,2)` |
| `map` | **实线箭头**（不占节点）| 中性深色 | `f : G → H` |
| `action` | **虚线方** + 作用线 | 绿 | `共轭作用(G)` |
| `number` | — | — | **不上画布**，进左栏「数值」区 |

两条正交编码：

- **形状 = 类型**（群=方 / 集合与子群集=圆 / 作用=虚线方 / 映射=箭头）
- **颜色 = 来源**（蓝 = 用户声明，紫 = 运算产生，绿 = 作用）

**类型改变是最强视觉信号**：`⟨S⟩` 把集合变成群，节点从**圆变方**，表示"结构升级"。
（`Z(G)` / `[G,G]` / `C_G` / `N_G` / `ker f` / `im f` / `⟨S⟩` 这类子群都升级为真群对象——用 core 的
`buildSubgroupGroup`，元素沿用母群对象、id 一致——所以 `Z(Z(G))` 是合法的。**U0 已落地**。）

节点状态：算中 / 已算 / 出错。

## 3. 输入层

### 3.1 三种输入形态

| 形态 | 适用 | 例子 |
|---|---|---|
| **文本定义** | 群 / 集合 / 数值 | `G = D_4`、`P = pSub(G, 2)` |
| **对象编辑器** | **映射 / 作用** | 列出 G 的生成元，逐个填像 |
| **搭积木** | 集合构造 | 分面表格就地筛选（见 §6）|

映射与作用**无法用一行文本表达**——同态由生成元的像唯一决定（数学上也是唯一正确的做法）。

### 3.2 输入框：两块（名字 | 表达式）—— ✅ 已落地（U1）

```
┌──────┬─────────────────────────────────────┬──────┐
│ 名字  │ 表达式                               │ 添加  │
│(可空) │                                     │      │
└──────┴─────────────────────────────────────┴──────┘
  B        {x ∈ A_4 : ord(x) = 2}
 ──────────────────────────────────────────────────────
 名字留空 → 自动命名「B」（已避开注册表的 83 个调用名）
```

- **名字栏留空 → 自动命名**：`A, B, D, F, I, …`（即 `A, B, C, …, Z, A₁, B₁, …` 去掉被占用的）。
  名字栏的 `placeholder` 直接显示**将分配的那个名字**——"留空"不是盲盒。
- **自动命名必须避开三类名字**，否则会静默遮蔽功能。名单由注册表自动导出（`gal/naming.ts`），**不手写**：
  1. 已用过的对象名（大小写不敏感）
  2. **注册表的所有调用名**（83 个：`z` / `c` / `sub` / `ord` / `ker` / `closure` …）——
     否则自动生成 `Z = …` 会把 `Z(G)` 这个操作名遮掉，而这是**静默**的
  3. 保留单字母 `e`（单位元）· `p`（素数）· `G` / `H`（惯用群名，留给用户手写）
- **手写名字只拦两件事**：非法字符、与已有对象重名。命中操作名**只提醒不拦截**
  （`Z = Z(G)` 是用户的明确表达，系统不该管；但要让他知道自动命名会跳过它）。
- **表达式栏边打边校验**，复用求值器本身，所以"预览"和"提交后得到的"必然一致：
  - 合法 → `✓ [作用] 共轭作用(D₄) · |Ω| = 8`（类型 chip + 标签 + 副行）
  - 非法 → 红字 + core 的**定向提示**（可用写法清单）；「添加」同时置灰
- 名字提醒与表达式预览**并存两行**——手写 `sub` 这种名字时，提醒不该被预览挤掉。
- 兼容**整行粘贴**：名字栏空着、表达式栏贴 `G = D_4`，自动拆成名字与表达式
  （左半边不像名字的，如 `x^2 = e`，整体当表达式）。
- 快捷键：`Enter` 提交 · `Esc` 清空两栏。

### 3.3 输入分层（同一个表达式栏，门槛从低到高）

| 门槛 | 方式 | 例子 |
|---|---|---|
| 零 | 目录点选 | 群目录手风琴（`getAllSmallGroups()`）|
| 零 | 记号 | `S_4` · `A_4` · `GL(2,3)` · `SmallGroup(16,13)` · `F21` |
| 低 | 构造 | `C_3 × C_2` · `G / N` · `A ∩ B` · `A \ B` · `A · B` · `⟨S⟩` |
| 低 | 生成元 | `⟨(123),(12)⟩`（母群未定，交记号解析）· `闭包(G, (123))`（在 G 里生成）|

记号解析走 `parseGroupNotation`（本地优先：能本地建群就不退化到后端）。
**元素参数走 `resolveElement`**，接受 id / label / value / 循环记号——所以 `ord(S_4, (123))` 合法。

**关键设计**：对象与操作在输入层**同构**——都是"定义一行"。用户只需一套心智模型：**定义一行，画布上长一个东西。**

## 4. 操作入口：三个入口 = 一张表

### 4.1 地基：`opsFor(selection)` —— ✅ 已落地（U0）

注册表（`apps/web/src/gal/ops.ts`）每条操作声明**命名参数 + 类型**：

```ts
type ParamType = 'group' | 'subset' | 'action' | 'map' | 'element' | 'prime' | 'int'

interface OpParam { name: string; type: ParamType; optional?: boolean }
interface OpDef  { /* … */ params: OpParam[]; arity: number; optional?: number }
```

七个参数类型不是 `ValueType` 的复读——它回答的是**"用户选中画布上的什么，就能把这个参数填上"**：

| 类型 | 画布上能填 | 说明 |
|---|---|---|
| `group` | 群节点 | |
| `subset` | 圆节点（元素集 / 子群集）| 也接受群节点，见下 |
| `action` | 作用节点 | |
| `map` | **✗** | 映射不占节点、只画边，要等 U3 的对象编辑器产出 |
| `element` | **✗ 标量** | 元素记号（`id` / `label` / **循环记号 `(123)`**），操作内部走 `resolveElement` |
| `prime` | **✗ 标量** | 素数 |
| `int` | **✗ 标量** | 整数 |

**约定：标量参数只能排在参数表末尾。** `opsFor` 依赖这条做前缀匹配；模块加载时有断言，声明与 `arity + optional` 对不上会直接抛错。

`subset` 接不接受**群节点**，取决于本操作前面有没有群参数：

- 前面**没有**群参数（`∩` `∪` `\` `·`）——群总是可以当集合读，接受；
- 前面**有**群参数（`G/N`、`C_G(G,S)`）——要求它是其中某个的子群（`isSubgroupElementSet`）。
  否则"`A × B` 的 B"也会被当成集合，选中两个群就会冒出一堆多余的候选。

于是派生一个纯函数，**三个入口共用**：

```ts
opsFor(selection: GalValue[]): OpDef[]     // 按参数类型序列前缀匹配
```

三条规则：

1. 选中的值按顺序逐参匹配（前缀）；
2. 剩下的必需参数**必须是标量**——它们可以由用户在输入框里补，所以不算"还缺一个对象"；
3. 需要再选一个对象的，不出现：选中一个群时没有 `G × H`，得再选一个群。

| 选中 | 可做（节选，20 条 → 27 条）|
|---|---|
| 一个群 `A₄` | `Z` · `[G,G]` · `Aut` · `Sub` · `pSub` · `Syl` · `正规子群` · `共轭作用` · `正则作用` · `⟨G,…⟩` · `ord`（共 11 条）|
| 两个群 | `G×H` |
| 群 + 子群（可以是升级后的群对象）| `G/N` · `C_G` · `N_G` · 交/并/差/积集 |
| 一个作用 | `轨道` · `稳定子` · `不动点` |
| 一个集合 | `⟨S⟩` |
| 一个映射 | `ker` · `im` |
| 空 | 建群（记号 / 目录，不进 `opsFor`）|

**这解决了"操作别扭"**：入口原来是死的（一张长列表），操作是活的（随选中对象变），两者靠用户脑中对齐。补上参数类型后，对齐由系统做。

**U0 已落地的第一个入口**：左栏「可用操作」面板在选中画布对象后切成"可用于「X」· 可用 N 条"（可一键切回全部 27 条）。径向菜单（§4.3）与工具条（§4.4）是同一张表的另外两个前端，U2/U4 再接。

### 4.2 交互状态机

```ts
type Interaction =
  | { kind: 'idle' }
  | { kind: 'selected'; target: string }                    // 单击对象 → 径向按钮 + 竖卡
  | { kind: 'menu'; target: string }                        // 径向展开
  | { kind: 'pending'; opId: string; picked: string[] }     // 等参数（多元操作）
  | { kind: 'editor'; opId: string; picked: string[] }      // 弹构建器（映射 / 描述式）

type LayoutMode = 'auto' | 'manual'
```

```
idle ──click(node)──→ selected ──click(径向)──→ menu
menu ──click(一元操作)──→ 执行 ──→ selected(新对象)
menu ──click(多元操作)──→ pending(opId,[node])
idle ──click(工具条)──→ pending(opId,[])
pending ──click(node)──→ pending(opId, picked+[node]) ──凑够 arity──→ 执行 或 editor
pending ──Esc / 再点工具条──→ idle
selected ──点空白──→ idle
```

`pending` 时必须有明确反馈：十字光标 + 顶部提示条「选择源群 (1/2) · Esc 取消」+ 已选节点高亮。

### 4.3 径向菜单：三类两层

选中对象后，其旁边出现圆形按钮，点开环绕展开。一个群有 15+ 个可做操作，**平铺一圈太挤，所以按行为分三类**：

| 类 | 行为 | 内容（以群 A₄ 为例）|
|---|---|---|
| **看** | 只填竖卡，不产生对象 | 基本信息 · 元素表 · 所有子群 · 共轭类 · 陪集分解 · 结构序列 · 识别 |
| **算** | 产生新对象（一元）| `Z` · `[G,G]` · `Aut` · `Sub` · `pSub` · `Syl` · `正规子群` · `共轭作用` · `正则作用` |
| **造** | 进入 pending（多元）| `G/N` · `G×H` · 映射 `f:G→H` · 自定义作用 |

### 4.4 顶部工具条

```
[群目录▾] [映射] [积] [商] [作用] [闭包] [集合] [操作表]        布局: 自动 / 手动
```

- **群目录**（左上角方形按钮 → 手风琴）：数据源 `getAllSmallGroups()`，按阶分组；点选即插入一行定义。
- **功能按钮**：点一下进入 `pending`，再点对象选参数（§4.2）。「映射」即：点映射 → 点源群 → 点目标群 → 弹构建器。
- **操作表**：一个「查表」modal，全量注册表按机制分组 + 搜索。**不是主入口**，是"我想不到要做什么"时的目录。

## 5. 左栏两态

左栏 320px 装不下输入框与竖卡并存。但竖卡随径向菜单开关而收放，**它是临时详情而非居民**，所以两态切换、不并存：

| 状态 | 内容 | 进入 |
|---|---|---|
| **输入态**（默认）| 三区（对象 / 操作 / 数值）+ 两块输入框 | 点空白 / 点返回 |
| **详情态** | **竖卡**：对象卡片 + 分区列表；输入区**折叠成一行**，顶部一个返回按钮 | 单击画布对象 |

竖卡的分区（对应 §4.3 的「看」类）：基本信息 · 元素表 · 子群列表 · 共轭类 · 陪集分解 · 结构序列 · 识别。

**数据源优先级**：
1. `getPrecomputed(group)` —— 目录群**零计算**（子群 / 正规子群 / 共轭类 / 中心 / 是否单 全在库里）
2. `listCosetStripSubgroups(group)` —— 子群列表用它（**按共轭轨道合并**：A₄ 的 6 个 C₂ 合成一项，带 `structure` / `isNormal` / `orbitSize` / `index`）
3. `findAllSubgroups` —— 兜底

超过 `ENUMERATION_LIMIT`(144) 时**截断 + 提示 + 可强制**（不静默失败）。

## 6. 集合构造器

`{x ∈ A₄ : x² = e}` 这类集合，有两条前端，**编译成同一个 AST**：

```
文本定义  B = {x ∈ A₄ : ord(x) = 2}  ┐
                                      ├─→ FilterSpec ─→ 筛(枚举(域,类型), 谓词) ─→ subset 对象
点击构造  元素表 → 点「阶」列 → 选 2  ┘        ↑
                                      （点击流把等价文本回填到输入框）
```

```ts
interface FilterSpec {
  domain: Ref
  from: 'elements' | 'subgroups'
  pred: AttrPred | WordPred
  combine?: { op: '∧' | '∨'; right: AttrPred | WordPred }
}
interface AttrPred { kind: 'attr'; attr: AttrName; op: '=' | '|' | '∈'; value: unknown }
interface WordPred { kind: 'word'; lhs: string; rhs: string; vars: string[] }   // 例 x^2 = e
```

**两条前端不是竞争关系。** 点击流**顺手把等价文本写出来**——不用二选一，点击流替你写出那行文本，下次你就能直接打。用户是"看着语法被写出来"学会的，这是这个功能的真正教学价值。

### 6.1 分面表格（不是向导）

`元素列表 → 属性 → 阶 → 2 → 固化` 如果做成向导，有两个毛病：**一次性的**（生成后选择状态丢失，改成 3 要从零重来）、**不可见的**（5 步才看到东西）。

修法：竖卡的列表做成**带分面的表格**——列头可点、就地筛选、可撤销：

```
┌ 元素表 ──────────────────────────────────────┐
│ 元素    阶▾    ∈Z?    共轭类   中心化子        │  ← 列头可点 = 分面
│ e       1      ✓      1        A₄            │
│ (12)    2      ✗      2        C₂×C₂         │
│ (123)   3      ✗      4        C₃            │
├──────────────────────────────────────────────┤
│ 筛选：阶 = 2 · 3 个元素                       │  ← 实时
│ = {x ∈ A₄ : ord(x) = 2}            [固化 → B] │  ← 实时生成的表达式
└──────────────────────────────────────────────┘
```

**关键：筛选状态不是 UI 状态，它是对象表里的一行。**
于是"可再编辑"是**免费**的——点画布上的 `B` → 竖卡回到筛选态、`2` 还亮着 → 改成 `3` → 整图自动重派生（"对象表 = lines 的纯函数"天然支持）。

### 6.2 「类型 × 属性」表的第二重身份

[ARCHITECTURE.md](ARCHITECTURE.md) §4 那张表原本只是"筛的谓词库"，它**同时是分面表格的列定义**：

| 对象 | 分面列 |
|---|---|
| 元素 | 阶 · ∈Z? · 共轭类 · 中心化子 |
| 子群 | 阶 · 指数 · 正规? · 极大? · Sylow? |
| 群 | 阶 · 交换? · 循环? · 单? · 可解? · 幂零? |

**一处定义，两处消费（筛选 + 展示）；列随选中对象类型自动变。** 所以同一个机制既能造 `{x : 阶=2}`，也能造 `{H : 正规}`。

### 6.3 属性谓词 vs 字谓词

| | 例 | 有列可点吗 | 实现 |
|---|---|---|---|
| **属性谓词** | `阶 = 2` · `正规` · `属于中心` | 有（分面下拉，可补全）| core 属性 + 枚举筛选 |
| **字谓词** | `x² = e` · `xy = yx` · `[x,y] = e` | 无（只能打字）| `parseWord(text, gens)` → 代入 `group.multiply` 折叠 → 比 `identity`；`parseRelationEquation` 校验 `f=e` / `f₁=f₂` 形式 |

两者用 `∧ ∨` 组合（即 ARCHITECTURE §4 的"写死 + 少量组合"），**不开放任意表达式**（不写 lambda）。

**属性谓词可自动翻译成字谓词**：`阶 = 2 ⇔ x² = e`。这不是冗余——**这正是证明里"为什么等价"的那一步**。

### 6.4 固化出的对象

固化结果是一个 **subset 对象**：画布上一个**圆** + 颜色（对齐 GroupViz 的 `{label, color, isSubgroup, isNormalSubgroup, type}` + `SUBSET_COLORS`）。

**若它恰好是子群，系统给提示但绝不自动改类型**：

> 这其实是个子群（V₄），要不要升级成群对象？

**对象类型是用户的心智模型，系统悄悄改会造成"这到底是集合还是群"的混乱**；但升级入口必须在手边（一次点击，不藏进菜单）。
升级用 `subgroupFromElementIds` 校验、`subgroupStructureSymbol` 命名、`buildSubgroupGroup` 造群。

## 7. 操作的构成与画布的边

### 7.1 操作 = 结果对象 + 结构伴生

群论操作很少只"吐一个结果"，通常还伴生一个结构关系：

| 操作 | 结果对象 | 伴生结构 | core 落点 |
|---|---|---|---|
| `G / N` | 商群 Q | 投影 `π : G → Q` | `naturalProjectionMapping` |
| `H ≤ G` | 子群 | 包含 `H ↪ G` | `subgroupInclusionMapping` |
| `G × H` | 积群 | 两个投影 | `directProductProjectionMapping` |
| `Z(G)` · `[G,G]` · `⟨S⟩` | 子群 | 包含映射 | 同上 |
| `共轭作用(G)` | 作用 | 作用线 `G ↷ Ω` | `computeConjugationPerms` |

**这些伴生结构就是交换图上箭头的真正来源。交换图不是用户手画的，是操作长出来的。**

### 7.2 三种边

| 边 | 样式 | 含义 | 参与交换图？ |
|---|---|---|---|
| **map** | 实线箭头 + 名称标签 | 数学中的映射（一等对象）| 是 |
| **action** | 绿色实线 + `↷` | 群作用 | 是 |
| **provenance** | 淡虚线 | "该节点由某操作算出"（辅助）| 否 |

来源线**默认显示，可全局关闭**。

## 8. 布局

### 8.1 规则

- **分层**：`level = 依赖链长度`（输入对象 0，其派生结果 1 …），层号小者在上；同层 **y 对齐**
- 同层按 x 排序后**水平去重叠**（最小间距 + 整层回正）
- 箭头走直线；有映射关系时按映射方向定层
- 节点尺寸由**标签实测宽度**决定（CJK ≈ 1em / 拉丁 ≈ 0.58em），整体**统一缩放**（连字号一起缩放）

引擎：`@groupviz/core` 的 `computeLatticeLayout(nodes, edges, opts)`；拥挤时用其 **LOD 三档**（`full` 名片 → `compact` 胶囊 → `dots` 点）。

### 8.2 自动 / 手动模式

| 模式 | 行为 |
|---|---|
| **auto**（默认）| 系统按数学惯例自动排布（第一同构定理 = 方形，短正合列 = 链式）|
| **manual** | 用户拖动节点、自行摆形状 |

手动模式的规则：

- **钉住语义**：一旦手动移动过某节点，该节点被"钉住"，后续新增对象仍自动布局但**绕开**它，不重置用户摆好的图
- **吸附网格**：拖动时吸附到淡点阵
- **一键恢复自动**：手动模式下顶部显示「手动布局」徽标 + 一个「恢复自动」按钮
- **持久化**：位置覆盖层按对象 id 存 localStorage

**与 GeoGebra 的关键区别**：Galculator 的节点位置是**结构分层**，不是数值坐标。拖拽是"人为选择的表达"，**不改变数学**。

## 9. 数值区（栈）

- **位置**：左栏第三区，在对象 / 操作之下
- **内容**：标量结果按计算顺序累积（`n = 2`、`C(12,4) = 495`、`|X| mod 2 = 1`）
- **交互**：点击某行 → 插回输入框，参与后续运算
- **语义**：证明过程中的临时量，算完即弃（栈式）
- **分工原则**：结构化对象上画布；纯数值进数值区

## 10. 节点浓缩

节点过多时允许浓缩，但**必须分两类、视觉上区分**：

| | 数学浓缩 | 视觉折叠 |
|---|---|---|
| 含义 | 有确定的数学内容 | 无数学含义，纯收纳 |
| 视觉 | **复合节点**（内部可见结构）| **分组框**（仅收起）|
| 例子 | 商 `G/N`（N 的每个陪集压成一点）、共轭轨道浓缩 | 步骤过多，收起已完成的一段 |

**绝不能混为一谈**——否则用户会误以为折叠的节点有代数含义。

**数学浓缩已有先例**：GroupViz `Group` 类型带 `cosetMemberLabels` / `cosetInternalEdges` / `cosetInternalLayout`，用于商群节点内部渲染正规子群的 Cayley 图；`mergeLatticeByConjugacy` 把子群格按共轭轨道压成轨道格。**直接复用。**

## 11. 画布图（CanvasGraph）

画布图是那块**背景板**：承载节点与边，布局引擎在它上面排位。
**由对象表派生，不是手画的**（与实现对齐，见 `apps/web/src/gal/`）：

```ts
// value.ts
type ValueType = 'group' | 'elements' | 'subgroups' | 'map' | 'action' | 'number'

// types.ts
interface GalObject {
  id: string                       // 对象名
  origin: 'input' | 'derived'      // 颜色来源
  label: string                    // 主行
  sub?: string                     // 副行
  def: string                      // 原始定义（等号右侧）
  sources: string[]                // 来源线目标（由参数链自动收集）
  value: GalValue                  // 6 类值之一
  opId?: string                    // 命中的注册表 id
  recipe?: string                  // 配方（解释用元数据）
  note?: string
}
interface CanvasNode extends GalObject { shape: 'group' | 'set' | 'action'; level: number }
interface GalEdge { id: string; kind: 'map' | 'action' | 'provenance'; from: string; to: string; label?: string }
interface CanvasGraph { nodes: CanvasNode[]; edges: GalEdge[] }
```

**派生规则**（三条）：

1. 每个对象 → 一个节点（`number` 除外，它进数值区；`map` 不占节点，只画边）
2. 每个操作的源 → 一条来源线（`sources` 由参数链自动收集，不是每个操作手写）
3. 操作若带**结构伴生**（§7.1）→ 额外生成 `map` / `action` 边

> `map` 的值类型与派生分支已就位，但**当前没有生产者**——需要 §3.1 的对象编辑器产出（U3）。
