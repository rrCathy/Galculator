# UI 重构规划（规划稿，含待拍板项）

> **已归档**（2026-09-16）。5 条待拍板项已全部定案，内容并入 `docs/INTERACTION.md` **v2**；本文件仅作历史记录。

> 这份是**规划稿**，不是已定规范。拍板后折进 [INTERACTION.md](INTERACTION.md)（升 v2）并删除本文档。
> 它回答一件事：**怎么把操作入口从"全局列表 + 手打语法"改成"在对象旁边完成"**。

## 0. 一句话

十条意见里，八条指向同一个内核：**操作入口与操作表脱节了**。
注册表已经是唯一真相，但它少了一列——**参数类型**。补上这一列，
`opsFor(选中对象)` 就能自动算出"这个东西能做什么"，于是
**径向菜单 / 顶部功能按钮 / 查表面板** 三个入口一次到位，互不重复劳动。

## 1. 十条意见归类

| 类 | 条目 | 性质 | 落点 |
|---|---|---|---|
| **缺操作面** | 1 映射 · 1.5 集合运算 | 功能缺口 | U0 引擎侧 + U3 编辑器 |
| **输入重构** | 2 别扭 · 2.1 两块输入框 + 自动命名 | 输入模型 | U1 |
| **入口重构** | 2.3 手风琴 + 径向菜单 + 竖卡 · 2.4 查表 · 2.5 功能按钮 | **核心** | U2 / U4 |
| **画布能力** | 2.2 可交互 · 2.6 拖动 + 手动布局 | 画布模式 | U5 |
| **元能力** | 2.7 宏 | 推后 | U6 |

理念：**用户应该在对象旁边完成他想要的操作。**

## 2. 核心判断：三个入口 = 一张表

现在的注册表每条操作声明了 `arity`，但**没有声明参数是什么类型**。补一个字段：

```ts
interface OpParam {
  name: string                    // 'G' | 'H' | 'p' | 'x'（**命名参数**，供表单与宏引用）
  type: ValueType | 'element' | 'prime' | 'int'
  optional?: boolean
}
interface OpDef { /* … */ params: OpParam[] }
```

于是派生出一个纯函数，**三个入口共用它**：

```ts
opsFor(selection: GalValue[]): OpDef[]      // 按参数类型序列匹配
```

| 选中 | `opsFor` 给出（节选） |
|---|---|
| 一个群 `A₄` | `Z` · `[G,G]` · `Aut` · `Sub` · `pSub` · `Syl` · `正规子群` · `共轭作用` · `正则作用` · `G/N`(待第二参) · `G×H`(待第二参) · 映射(待第二参) |
| 两个群 `G`,`H` | `G×H` · `映射 f:G→H` |
| 群 `G` + 子群 `N` | `G/N` |
| 一个作用 `A` | `轨道` · `稳定子` · `不动点` |
| 一个集合 `S` | `⟨S⟩` · 交/并/差/积集（待第二参）|
| 空 | 建群（记号 / 目录）|

**这直接解释了"操作别扭"的根因**：入口是死的（一张长列表），操作是活的（随选中对象变），两者靠用户脑子对齐。补上参数类型后，对齐由系统做。

> 顺带一个额外收益：**命名参数**是宏（2.7）和 Proof Spec 的共同前置。Proof Spec 的 `compute.args` 现在按位置引用，改成按名引用后，模板的可读性与宏的参数化都会顺很多。

## 3. 侦察结论：core 已经把料备好了

这轮把 `@groupviz/core` v2.3.0 的相关 API 全扫了一遍，**四个发现改变规划形态**：

| # | 发现 | 落点 | 意味着 |
|---|---|---|---|
| 1 | **`buildSubgroupGroup(parent, elements, symbol, generators?)` → `Group`** | `algebra/semidirectDecompositions` | **子群可以变成真正的群对象**（元素沿用母群对象，id 一致）。于是 `Z(A₄)` 出**方**节点，可以继续 `Z(Z(G))`、`Sub(Z(G))`、`Z(G) × H`、`G/[G,G]` |
| 2 | **`resolveElement(group, ref)`** 接受 id / label / value / **循环记号** | `algebra/elementRef` | 元素参数不再只认 label。`ord(S_4, (123))` 可用；现在 `looksLikeLiteral` 那个 hack 可以退休 |
| 3 | **结构伴生映射全是现成的**：`naturalProjectionMapping` · `subgroupInclusionMapping` · `directProductProjectionMapping` · `trivialMapping` | `algebra/homomorphisms` | INTERACTION §4 那条"操作 = 结果对象 + **结构伴生**"能从设计变成现实：`G/N` 自带投影 `π`、`H ≤ G` 自带包含 `H ↪ G`、`G×H` 自带两个投影。**交换图上终于有实线箭头**，不再是清一色虚线 |
| 4 | **`extendFromGenerators(source, target, Map<生成元名, 像引用>)` → `HomomorphismMap \| null`** + `verifyHomomorphism` 返回 `violation{a,b,lhs,rhs}` | 同上 | 映射构建器的**引擎侧已经完整**：`getGeneratorElements(g)` 列出生成元 → 用户逐个填像 → 自动补全并校验。UI 只需一张表单 |
| 5 | **`listCosetStripSubgroups(group)`** 出按共轭轨道合并的子群候选，带 `structure` / `isNormal` / `orbitSize` / `index` | `algebra/cosetStrip` | 竖卡的「所有子群」直接用它，而不是 `findAllSubgroups` 直出 9 条原始数据 |
| 6 | **`getPrecomputed(group)` → `{subgroups, normalSubgroups, conjugacyClasses, center, isSimple}`** | `groups/SmallGroups/registry` | **目录群零计算**：A₄ 的子群/共轭类/中心直接从库里读 |
| 7 | **`subgroupStructureSymbol(group, elementIds)`** | `algebra/subgroups/detection` | 子群能报出名字（`C_2×C_2` / `D_4`），不必先造成 Group |
| 8 | **`getAllSmallGroups()` → `SmallGroupEntry{order,index,group,precomputed}`** | 同上 | 2.3 的手风琴目录数据源；且**自带 Group 对象**，点选即用 |

**结论：这一轮没有任何一件事需要等后端、也没有一件事需要重新发明。** 全部是前端组装。

## 4. 交互状态机（新增的核心）

2.3（径向菜单）、2.5（功能按钮选两个对象）合起来要求画布有一个显式状态机：

```ts
type Interaction =
  | { kind: 'idle' }
  | { kind: 'selected'; target: string }                              // 单击对象 → 径向菜单 + 竖卡
  | { kind: 'menu'; target: string }                                  // 径向展开
  | { kind: 'pending'; opId: string; picked: string[] }               // 2.5：等参数
  | { kind: 'editor'; opId: string; picked: string[] }                // 弹构建器（映射 / 描述式）

type LayoutMode = 'auto' | 'manual'                                   // 2.6
```

转移：

```
idle ──click(node)──→ selected ──click(径向)──→ menu
menu ──click(一元操作)──→ 直接执行 ──→ selected(新对象)
menu ──click(多元操作)──→ pending(opId,[node])
idle ──click(工具条)──→ pending(opId,[])
pending ──click(node)──→ pending(opId,picked+[node]) ──凑够 arity──→ 执行 或 editor
pending ──Esc/再点工具条──→ idle
selected ──click(空白)──→ idle
```

`pending` 时画布要有明确反馈：光标变十字 + 顶部提示条「选择源群 (1/2) · Esc 取消」+ 已选节点高亮。

## 5. 布局与空间（左栏 / 竖卡 / 画布）

2.1 要输入框在左侧，2.3 要竖卡也在左侧 —— 320px 装不下两者并存。
但你说了"**收起按钮后竖卡也收起**"，说明竖卡是**临时详情**而非常驻区，所以不冲突，只需给左栏一个状态：

| 左栏状态 | 内容 |
|---|---|
| **输入态**（默认） | 三区（对象 / 操作 / 数值）+ 自动命名输入框 |
| **详情态**（选中对象时） | 竖卡（对象卡片 + 分区列表）；输入区**折叠成一行**，顶部一个返回按钮 |

切换规则：单击对象 → 进详情态；点空白 / 点返回 → 回输入态。**不并存，不挤压。**

画布区（右侧舞台）：

```
┌─ 顶部工具条 ── [群目录▾] [映射] [积] [商] [作用] [闭包] [集合] │ 布局: 自动/手动 ─┐
├──────────────────────────────────────────────────────────────────┤
│                     交换图画布（SVG）                              │
│   节点旁：径向按钮（选中时出现）                                     │
├──────────────────────────────────────────────────────────────────┤
│  提示条（pending 时）/ 详情预览（原有 detail 条，可保留）            │
└──────────────────────────────────────────────────────────────────┘
```

- **2.3① 群目录**：左上角方形按钮 → 手风琴展开，来源 `getAllSmallGroups()`，按阶分组（C₂/C₃/…/S₄/A₅/Dₙ/GL(2,3)/Q₈/…）。点选即插入一行定义。
- **2.4 查表**：顶部工具条右端一个「操作表」按钮 → 弹出 modal，按机制分组的全量注册表（现在的 palette 直接搬过去），带搜索。
- **2.6 布局开关**：顶部右侧「自动 / 手动」。手动模式下可拖动节点。

## 6. 输入框重设计（2.1）

```
┌──────────┬──────────────────────────────┐
│ 名字(可空) │ 表达式                        │  [加]
└──────────┴──────────────────────────────┘
   A         D_4
```

- 名字栏留空 → **自动命名**：`A, B, C, …, Z, A₁, B₁, …`
- 自动命名**必须避开三类名字**，否则会静默遮蔽功能：
  1. 已用过的对象名
  2. **注册表的所有调用名**（`C` / `Z` / `C_G` / `N_G` / `Sub` / `Aut` / `Syl` / `ord` / `分解` …）—— 否则自动生成 `Z = …` 会把 `Z(G)` 这个操作名遮掉
  3. 保留单字母 `e`（单位元）· `p`（素数）· `G` `H`（惯用群名，留给用户手写）
- 表达式栏边打边校验（沿用现在的问题区），回车提交。

## 7. 竖卡内容（2.3②）

选中对象后，径向菜单按**三类**展开（一个群有 15+ 个可做操作，平铺太挤）：

| 类别 | 行为 | 内容（以群 A₄ 为例）|
|---|---|---|
| **看** | 只填竖卡，不产生对象 | 基本信息 · 元素表 · 所有子群 · 共轭类 · 陪集分解 · 结构序列 · 识别 |
| **算** | 产生新对象（一元）| `Z` · `[G,G]` · `Aut` · `Sub` · `pSub` · `Syl` · `正规子群` · `共轭作用` · `正则作用` |
| **造** | 进入 pending（多元）| `G/N` · `G×H` · 映射 `f:G→H` · 自定义作用 |

数据源优先 `getPrecomputed(group)`（**库群零计算**）；非库群走 `listCosetStripSubgroups` / `findAllSubgroups`，并按 `guards.ts` 的 `ENUMERATION_LIMIT(144)` 截断 + 提示。

## 8. 阶段划分 U0–U6

每个阶段都独立可验收，且都有**可见的 UX 变化**。

| 阶段 | 内容 | 可见成果 | 依赖 |
|---|---|---|---|
| **U0** 注册表补参数类型 | `params` + `opsFor(selection)`；**顺手补集合运算叶子**（∩ ∪ \ ·）；映射引擎侧 op（`createMap`/`verify`）；元素参数改走 `resolveElement` | `A ∩ B`、`⟨S⟩`、`ord(S_4,(123))` 可用；`Z(A₄)` 升级为**方节点**（`buildSubgroupGroup`）| — |
| **U1** 输入框两块 + 自动命名 | 名字栏 / 表达式栏；自动命名服务；Esc 清空 | 不再需要自己想名字 | U0 |
| **U2** 画布交互状态机 + 径向菜单 + 左栏详情态 | §4 状态机；§7 三类菜单；竖卡 | **在对象旁边就能操作**（理念落地）| U0、U1 |
| **U3** 映射构建器 + 结构伴生箭头 | 生成元填像表单（`getGeneratorElements` + `extendFromGenerators` + `verifyHomomorphism`，违规给 `f(a)f(b)≠f(ab)` 定向提示）；`π` / `H↪G` / 积投影落地 | **交换图上第一条实线箭头**；`ker`/`im` 可用 | U2 |
| **U4** 顶部工具条 + 操作表 modal | 群目录手风琴（`getAllSmallGroups`）；功能按钮（映射/积/商/作用/闭包/集合）；查表 modal | 不用记语法，点着就能做 | U2 |
| **U5** **集合构造器**（见 §9） | 分面表格 + 属性谓词 + 字谓词 + 固化/再编辑 | `{x ∈ A₄ : x²=e}` 点着就能造出来，**并顺手写出等价文本** | U4 |
| **U6** 拖动 + 手动布局 | 位置覆盖层（按对象 id）+ **钉住语义**（手动移过的节点不再被自动重排）+ localStorage 持久化 | 可以自己摆出形状 | U2 |
| **U7** 宏（2.7） | 记录一串 `(opId, 命名参数)` 并重放 | 常用组合一键复用 | U3、**建议等 M1 Proof Spec 落地后**（见下）|

### 关于 U7 的诚实提醒

**宏和 Proof Spec 的 step 序列是同一个数据结构**（`(opId, 参数引用)` + 展示方式）。
区别只在：宏要么**纯重放**（绑定具体对象名，换对象要重录），要么**参数化**（形参 + 命名捕获 —— 这是个独立的小语言设计问题，不便宜）。

建议：**先纯重放**，等 M1 的 Proof Spec 执行器做出来，宏直接复用它，不另写一套。所以 **U7** 排在 M1 之后更省。

## 9. 集合构造：两条前端，一个 AST

用户构想（点击流）：

```
导入 A = A₄ → 点画布上的 A₄ → 竖卡「元素表」→ 点属性列「阶」→ 选 2
            → 收入新集合 B → 画布上出现 B
```

文本流：`B = {x ∈ A_4 : ord(x) = 2}`

**这两条不是竞争关系，是同一个 AST 的两个前端**（和"三个入口 = 一张表"同一个模式）：

```ts
interface FilterSpec {
  domain: Ref                        // A₄
  from: 'elements' | 'subgroups'     // 枚举什么
  pred: AttrPred | WordPred          // 筛什么
  combine?: { op: '∧' | '∨'; right: AttrPred | WordPred }
}
interface AttrPred { kind: 'attr'; attr: AttrName; op: '=' | '|' | '∈'; value: unknown }
interface WordPred { kind: 'word'; lhs: string; rhs: string; vars: string[] }   // 例 x^2 = e
```

两条前端都编译成 `FilterSpec` → 执行 `筛(枚举(域, from), pred)` → 产出 **subset 对象**。

**所以点击流不该是"向导"，它应该顺手把文本写出来给你看。**
这正是你那句"不如直接在输入框输入"的答案：**不用二选一——点击流替你写出那行文本，下次你就能直接打。**
（这也是这个功能真正的教学价值：用户是"看着语法被写出来"学会的。）

### 9.1 用户流程的真实问题：它是向导

`元素列表 → 属性列表 → 阶 → 2 → 固化` 有两个毛病：

1. **一次性的** —— 生成 B 之后，"阶 = 2"这个选择状态就没了；想改成 3 得从零重来
2. **不可见** —— 走完 5 步才看到东西；文本输入 1 步就出结果

修法：**把竖卡的列表做成"带分面的表格"（faceted table）**——就地筛选、可撤销、可再编辑：

```
┌ 元素表 ──────────────────────────────────────┐
│ 元素    阶▾    ∈Z?    共轭类   中心化子        │  ← 列头可点 = 分面
│ e       1      ✓      1        A₄            │
│ (12)    2      ✗      2        C₂×C₂         │
│ (34)    2      ✗      2        …             │
│ (123)   3      ✗      4        C₃            │
├──────────────────────────────────────────────┤
│ 筛选：阶 = 2 · 3 个元素                       │  ← 实时
│ = {x ∈ A₄ : ord(x) = 2}            [固化 → B] │  ← 实时生成的表达式
└──────────────────────────────────────────────┘
```

**关键：筛选状态不是 UI 状态，它是对象表里的一行。**
于是"可再编辑"是**免费**的——点画布上的 `B` → 竖卡回到筛选态、`2` 还亮着 → 改成 `3` → 整图重派生
（现有"对象表 = lines 的纯函数"架构本来就支持，一行代码都不用为它专门写）。

### 9.2 「类型 × 属性」表的第二重身份

架构 §4 那张表原本只是"筛的谓词库"。现在它**同时是竖卡表格的列定义**：

| 对象 | 分面列 |
|---|---|
| 元素 | 阶 · ∈Z? · 共轭类 · 中心化子 |
| 子群 | 阶 · 指数 · 正规? · 极大? · Sylow? · 正规化子 |
| 群 | 阶 · 交换? · 循环? · 单? · 可解? · 幂零? |

**一处定义，两处消费（筛选 + 展示）。列随选中对象的类型自动变。**
所以你的流程对**元素**可行，对**子群**（正规/极大/Sylow）一样可行——同一个机制，不用新设计。

### 9.3 属性谓词 vs 字谓词：都要

| | 例 | 有列可点吗 | 实现 |
|---|---|---|---|
| **属性谓词** | `阶 = 2` · `正规` · `属于中心` | 有（分面下拉，可补全）| core 属性 + 枚举筛选 |
| **字谓词** | `x² = e` · `xy = yx` · `[x,y] = e` | 无（只能打字）| **core 有现成件**（见下）|

`x² = e` 这种**是可做的**，不用退化成只有属性谓词：

- `parseWord(text, gens)` → `PresentationTerm[]`（`{g: 生成元序号, e: 指数}`）
- 逐个元素代入 → 用 `group.multiply` 折叠 → 与 `group.identity` 比对
- `parseRelationEquation(text, genNames)` 校验形式（必须 `f = e` 或 `f₁ = f₂`），返回规范化关系或定向错误

（上面两个都实测存在：`algebra/presentations/wordParser`。）

而且属性谓词能**自动翻译**成字谓词：`阶 = 2 ⇔ x² = e`。
这不是冗余——**这正是证明里"为什么等价"的那一步**，将来 Sylow 模板要用。

混合用 `∧ ∨` 组合，即架构 §4 已定的"写死 + 少量组合"。

### 9.4 与 Proof Spec 的关系（这才是重点）

`{x | x² = e}` 的三段（**枚举 → 筛 → 固化**）就是 Proof Spec 里一个 `compute` step。
所以这个构造器做出来，**Sylow I 模板里"取全体 pᵏ 元子集 X"那一步就有可视化构造方式了**；
粒度 C 的"只算计数不枚举"只是同一构造器加一个「只计数」开关（`binomialMod` 算 `|X|`）。

### 9.5 subset 对象：core 已有先例，对齐它

GroupViz 视图层已有 subset 概念（`types/view.d.ts`）：

```ts
{ label, color, isSubgroup, isNormalSubgroup, type: 'subset' | 'subgroup' | 'normal-subgroup' }
SUBSET_COLORS: string[]
```

**Galculator 的 `B` 就是 `subset`**：画布上一个圆（形状 = 类型），带颜色（同类集合区分）。
若它恰好是子群，可用 `subgroupFromElementIds` 校验、`subgroupStructureSymbol` 命名。
（要不要**自动升级成群对象**见 §10 待拍板第 5 条。）

## 10. 待拍板

1. **径向菜单的粒度**：我建议**三类两层**（看 / 算 / 造）—— 一个群的可做操作有 15+ 个，平铺一圈太挤。要不要更细（按机制分五类）？
2. **宏的范围**：**纯重放**（现在就能做，便宜）还是**参数化**（真宏，但要设计命名捕获，建议等 Proof Spec）？
