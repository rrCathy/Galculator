## 0. 触发

**四条差评**：① 台内造不出集合 ② 界面烂/别扭 ③ 中英混杂 ④ 不是探索精细结构的台，是"数控机床"。

**三条约束（逐轮加）**：
- **A. 台不必小** —— 占大半个屏幕没问题。
- **B. 遮挡靠半透明** —— 液体玻璃质感，画布在背后可见。
- **C. ★ 用符号按钮，不用功能文字** —— 「想想计算器，不都有按钮……用几个按钮来代替一堆功能文字？
  比如用『＋』按钮让用户导入对象。」**这是本稿的转轴。**

## 1. 使用场景

### 场景 1｜造一个东西：造 → 填 → 判，全程不下台
> 「造 {a,b,c}，给它一个运算，看是不是群。」
> **按 `＋`** 放入三个标号 → 键盘上出现「加运算」→ 长出**空运算表** → 边填边看**公理判定** → 改两个格子 → 成了。

### 场景 2｜探索一个群：放大镜
> 「S₄ 里到底有什么？」
> 点画布上的 S₄（或按 `＋` 导入）→ **明细区一屏铺开**（阶/元素/子群/正规/共轭类/Sylow/中心）
> → 想深挖某个子群，**点那一行** → 它成为新焦点，键盘换成"对这个子群能做的事"。

### 场景 3｜连续演算：结果留在台面
> 「算 Z(G)，再算 G/Z(G)，看是不是 C₂。」
> 焦点 G → **按 `Z`** → Z(G) 落到显示条 → 点它成为焦点 → **按 `/`** → G/Z(G) → 点它 → 明细区显示 `≅ C₂`。

### 场景 4｜（对照）画布管"关系"，工作台管"里子"
玻璃让两者**同屏**：画布在背后若隐若现，工作台在前景。

## 2. 病根 + 设计原则

**病根**：① 造的入口不在工作台（`workbench.ts#BENCH_EXCLUDED`）· ② 输入语法被当成显示名
（`interaction.ts#menuLabel` 从 `notation` 派生）· ③ 工作台是 op 清单，不是对象视图。

**七条原则**（前五条来自场景，后两条来自"计算器"这条约束）：

| # | 原则 | 落到形态 |
|---|---|---|
| P1 | **摊开，不折叠** | 进工作台＝把对象**放大**看，默认全可见 |
| P2 | **产物回台面** | 每次动作结果**落在显示条**并自动成为新焦点 |
| P3 | **可下钻** | 明细区每一项（子群、元素）都能点进去成为新焦点 |
| P4 | **造/读/做同台** | 不逼你先去别的面板 |
| P5 | **动作跟着焦点走** | 只显示相关操作，不把 34 条一次摊开 |
| P6 | **★ 符号 > 文字** | 每个操作＝一个**符号键**（`×` `⋊` `/` `Z` `≤` `Syl`…），中文全名放**悬停/显示条**。**这就是"计算器"** |
| P7 | **★ 键盘随焦点变** | 焦点是集合 ⇒ 只出"加运算/点集"键；是群 ⇒ 出群键；是映射 ⇒ 出 `ker`/`im`。**任何时刻屏上只有十来个键**（这才是"几个按钮"）|

## 3. 目标形态：一台半透明玻璃计算器

```
┌ 工作台（半透明玻璃 · 底部升起 · 默认 ~68vh，可拖 ~88vh）────────────────────┐
│ ① 显示条（计算器的"显示屏"）                                           ┌────┐ │
│   ┌─────────────────────────────────────────────┐                │ ＋ │ │
│   │  S₄ · 阶 24 · 非交换                          │                │导入 │ │
│   │  （或正在构造： S₄ × ▢ = …）                   │                └────┘ │
│   └─────────────────────────────────────────────┘                       │
├──────────────────────────────────────────────────────────────────────┤
│ ② 键盘（**符号键**；随焦点变；悬停出中文全名 + 一句说明）                    │
│                                                                      │
│   造新群   ×    ⋊     /     ⟨ ⟩    [G,G]   Aut   Inn                    │
│   子群     ≤    max    ⊴     Syl    p       C_G   N_G                    │
│   作用     ↷    ↺     Ω↷    G/H↷  Orb    Stab  Fix                      │
│   映射/集合 ker   im    ∩     ∪     \      ×      asSet                  │
│                                                                      │
│   ▲ 焦点是个**集合**时，只出「加运算 / 点集」两三个键，其余隐藏           │
├──────────────────────────────────────────────────────────────────────┤
│ ③ 明细区（大，铺开读）：当前对象/结果的**精细结构**                        │
│     基本 · 元素表 · 子群 · 正规/共轭类 · 运算表 · 公理                      │
└──────────────────────────────────────────────────────────────────────┘
```

**为什么这不是"数控机床"**（同一个"按钮"的两副面孔）：

| | 数控机床（被否的现状） | 计算器（本稿） |
|---|---|---|
| 样子 | `directProduct(A, B)` 一格格**文字** | `×` **一个符号** |
| 数量 | 34 条**一次全摊** | **随焦点变**，眼前只有十来个（P7）|
| 记忆 | 要读英文函数名 | 靠**符号 + 空间位置**认（像认得 `√`）|
| 中文 | 中英混杂 | 悬停/显示条给**中文全名 + 说明** |
| 主角 | 按钮 | **明细区**（对象的结构）+ **显示条** |

**`＋` 键**（P6 的点名需求）：开一个"放什么上台面"的小面板 —— 造点集 / 按标号造 / 从群库导入 / 造结构
（复用 `CatalogDock` 那三种造法，**不再要求先离开工作台去目录**）。

**⚠️ 不新造数据**：台面上的对象＝**画布同一份 `objects`**；新结果本就落成画布对象 ⇒ 自动上台面。

## 4. 玻璃质感（浅色主题）

```
background: rgba(252, 252, 255, 0.62);
backdrop-filter: blur(24px) saturate(180%);
border: 1px solid rgba(255, 255, 255, 0.6);
border-radius: 22px 22px 0 0;
box-shadow: 0 20px 60px rgba(0,0,0,.18), inset 0 1px 0 rgba(255,255,255,.7);
```
收起仍是**贴底胶囊**（不跳位）；画布**不重排**（`position: absolute` 浮层）。
