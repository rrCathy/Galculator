# 开发规划

## 技术栈定案

| 层 | 选型 |
|---|---|
| 前端 | React 19 + TypeScript + Vite |
| 后端 | 扩展 GroupViz GAP（FastAPI + GAP 4.16）|
| 复用 | `@groupviz/core` v2.3.0（npm，纯算法层）|
| 渲染 | `@groupviz/react` v2.3.0（10 个 Scene）+ 自研交换图画布 + KaTeX |

## 阶段划分

### 阶段 0 — 奠基：画布图最小闭环（M0）✅ 已完成

- **已交付**：pnpm monorepo + `apps/web`（Vite + React 19 + TS）；装 `@groupviz/*` v2.3.0；
  `CanvasGraph = derive(objects, ops)`（见 INTERACTION §10）+ `computeLatticeLayout` 分层布局；
  自研 SVG 交换图画布（节点卡 + 两类边）。
- **里程碑达成**：输入 `G = D_4`、`P = G x H`、`Z = Z(G)`，画布长出节点与边并自动分层（见 README 截图）。
- **遗留**：操作是 `evalDef.ts` 里硬编码的 if-else，只有 `Z(G)` 与 `×` 两条 —— **已由 M0.5 收口**。

### 阶段 0.5 — 按架构落地操作层（M0.5）✅ 已完成

- 目标：把操作层从"硬编码"换成 [ARCHITECTURE.md](ARCHITECTURE.md) 定义的**注册表 + 值类型**。
- 已交付：
  - 值类型扩到 **6 种**（`group` / `elements` / `subgroups` / `map` / `action` / `number`）+ 子群归一化（`Subgroup` / `PSubgroupInfo` / `SylowSubgroupInfo` 拉平为 `NormalizedSubgroup`）。
  - **`gal/ops.ts` 注册表**：20 个操作，每条声明 = 机制归类 + 调用名/中缀 + 参数个数 + 产出值类型 + core 落点 +（可选）配方 + 求值函数。覆盖六个机制：原子构造 5 · 作用导出 6 · 枚举+筛 4 · 迭代 1 · 属性 1 · 算术 3。
  - **`evalDef.ts` 五级分发**：对象引用 → 函数式调用 → 顶层中缀 → 记号建群；参数递归求值，**来源线自动从参数链收集**（不再是每个操作手写）。
  - **操作面板**（左栏「可用操作」）：由注册表按机制分组生成，点击插入模板——注册表驱动的第一个 UI 入口。
  - 画布新形状：**作用线**（绿色实线 + ↷）、子群集/元素集统一为圆；节点尺寸按标签实测宽度自适应，同层水平去重叠 + y 对齐。
- 里程碑达成：`P = pSub(G, 2)` 出「子群集」节点；`A = 共轭作用(G)` 出作用节点与作用线。
- 验证：`tsc --noEmit` 0 错误；core 逻辑 24/24 断言通过（`|Orb|×|Stab| = 2×4 = |G| = 8`）；真浏览器控制台零错误。
- **遗留**：`map`（映射）只有值类型与派生分支，无生产者——需「对象编辑器」（生成元填像）才能落地；`orbits` / `stabilizers` 的陪集作用分支、`半直积 ⋊`、识别类均待后续。
- 依据：ARCHITECTURE §2–§5。

### 阶段 U0 — 操作入口的地基 ✅ 已完成

- 目标：消掉"操作别扭"的根因（**入口是死的、操作是活的、两者靠用户脑中对齐**）——先让**系统知道**
  "选中什么就能做什么"。
- 已交付：
  - **注册表 27 条**（M0.5 的 20 + 新增 7）：每条声明**命名参数 + 类型**（`ParamType` 7 类）；
    模块加载时断言 `params.length === arity + optional` 且标量参数只在末尾，声明错了直接抛错。
  - **`opsFor(selection)`**：按参数类型序列做前缀匹配。末尾的标量参数（`element` / `prime` / `int`）
    视作"可由输入框补"，所以选中一个群会出现 `pSub(G, p)` / `Syl(G, p)`，但不出现 `G × H`。
    `subset` 对群节点的放宽是有条件的（前面有群参数时要求"是它的子群"），
    否则选中两个群会冒出一堆多余的商群候选。
  - **集合运算 4 条**：`∩` `∪` `\` `·`（同母群校验；积集走母群乘法）。产出 `elements` 而非群
    ——**固化集合不自动升级**（决策 ⑤）。
  - **闭包 `⟨S⟩`**：`closeUnderMultiply` 迭代到封闭，产出真群对象；也支持 `闭包(G, r2)`
    用上下文群解析元素记号（循环记号 `(123)` 走 `resolveElement`）。
  - **子群升级为真群对象**：`Z(G)` / `[G,G]` / `C_G` / `N_G` / `ker f` / `im f` / `⟨S⟩` 全部改走
    `buildSubgroupGroup`（`result: 'group'`），画布上**圆变方**，`Z(Z(G))` 合法；副行带上结构符号
    （`|Z| = 2 · C₂`）。
  - **映射引擎侧 2 条**：`ker` / `im`（吃 `map` 值 + 完整映射表）。`GalMap.mapping` 已备，
    生产者由 **U3 的映射构建器**补上（现已可用）。
  - **元素参数一律走 core `resolveElement`**：`ord(S_4, (123))` 合法。
  - **第一个入口**：左栏「可用操作」在选中对象后切成"可用于「X」· 可用 N 条"，可一键切回全部 27 条。
- 验证：`tsc --noEmit` 零错误；vite SSR 打包后 node 直跑 **52/52 断言**（集合运算、闭包阶、`Z(Z(G))`、
  `opsFor` 匹配表、ker/im、注册表自洽）；真浏览器（playwright）控制台零错误 + 6 节点 SVG 渲染正常。
- 依据：INTERACTION §2 / §3.2–3.3 / §4.1、ARCHITECTURE §5.1–5.2。

### 阶段 U1 — 输入框两块 + 自动命名 ✅ 已完成

- 目标：用户**不用自己想名字**，也不用记"哪个名字被占了"。
- 已交付：
  - `gal/naming.ts`：**保留名清单从注册表自动导出**（83 个调用名）+ 惯例单字母 `e` / `p` / `g` / `h`；
    `nextAutoName`（`A B D F …` → `A₁ B₁ …`，跳过已用名与保留名）、`checkName`（非法字符 / 重名**拦**，
    命中操作名**只提醒**）、`autoNamePreview`。
  - **输入框拆两块**：「名字(可空) | = | 表达式 | 添加」，名字栏 `placeholder` 直接显示**将分配的名字**。
  - **边打边校验**：复用 `evalExpr`（所以预览与提交结果必然一致）——合法就显示"会产出什么"
    （类型 chip + 标签 + 副行），非法就红字 + core 的定向提示；非法时「添加」置灰。
  - 名字提醒与表达式预览**并存两行**；兼容**整行粘贴**（`G = D_4` 自动拆分）；`Enter` 提交 / `Esc` 清空。
- 验证：`tsc` 零错误；**35/35 断言**——含一条强性质（连取 60 个自动名，全部避开保留名且互不重复）、
  名字体检各分支、以及"自动命名出的定义行真能建出对象且老写法照常"；
  playwright 真浏览器零错误，覆盖五态（非法→红+置灰 / 合法→预览 / 重名→拦 / 命中操作名→只提醒 / 留空提交）。
- 依据：INTERACTION §3.2。

### 阶段 U2 — 操作入口搬到对象旁边 ✅ 已完成

- 目标：**用户应该在对象旁边完成他想要的操作**（这是与 Desmos 最大的区别）。
- 已交付：
  - **交互状态机**（`gal/interaction.ts`，纯状态、可单测）：`idle → selected → menu → pending / fill`。
    `pending` 等**对象**参数（画布上接着点），`fill` 等**标量**参数（顶部补参条）——
    `fill` 是原方案漏掉的一档：`pSub(G, p)` / `ord(G, g)` 的末尾参数画布上点不出来。
  - **径向菜单**（`ui/RadialMenu.tsx`）：节点旁 `◎` 入口 → 三类两层（看 / 算 / 造）环绕展开。
    按钮用短标签、做边界钳制；「算」「造」的判定口径不同（见 INTERACTION §4.3）。
  - **一键执行**：点选出来的操作先被**编回一行文本**（`gal/compose.ts`），再交给 `evalExpr`——
    于是"点出来的"与"打出来的"行为必然一致，且用户**看得见系统替他写了什么**（左栏真多出一行，可读可改）。
    名字走 U1 的自动命名；同名同标签的重复计算去重，直接选中已有对象。
  - **pending 四件反馈**：顶部提示条（「选择「N」（集合/子群）· 第 2 / 2 个对象」）· 十字光标 ·
    已选节点换色加粗 · **不可点的节点变暗**（末一条是加出来的：点击失败的挫败感比高亮带来的便利更大）。
  - **左栏详情态（竖卡）**：点节点即切过去；按值类型分区（group 有基本信息/识别/元素表/共轭类/子群）。
    原先底部的详情条整体搬进来，底部不再占高度。
  - `Esc` / 点空白取消；执行失败的兜底提示条（菜单没有输入框，失败必须说出来）。
- 验证：`tsc` 零错误；**72/72 断言**（compose 组装、闭环"组装出来的行真能求值"14 条、算/造二分、
  `canPick`、状态机辅助共 8 组）；playwright 真浏览器零错误，走查十条路径
  （点节点 → 入口 → 三类 → 算类执行 → 补参执行 → 造类 pending → 点第二个参数执行 → Esc → 竖卡 → 返回）。
- **真浏览器抓到的 bug**：菜单第一层的「造」恒为空——误用 `opsFor` 去筛多元操作（它要求参数能被填满，
  所以单选一个对象时多元操作根本不在结果里）。改成直接遍历注册表 + `paramAccepts`。
- 依据：INTERACTION §4.2 / §4.3 / §5。

### 阶段 U3 — 映射构建器 ✅ 已完成（2026-09-16）
