## 本轮踩到的坑（都已补进 verify/README.md）
1. **`registry` 的相近匹配别用短别名**：单字母别名 `c`（组合数）是 `gcd` 的子串 →
   "是不是想用 C(n, k)" 这种驴唇不对马嘴的提示。加**长度 ≥ 2 门槛**。
2. **关系行在输入框里走的是 `evalExpr`，不是 `buildLines`**：走查一开始验错了路径
   （`buildLines` 的"缺少「=」"只在**已提交的定义行**上）。
3. **左上是两个抽屉**：「对象」= `origin === 'input'`、「操作」= `derived`（映射/核/像都在后者），
   而 `DockPanel` **收起时 body 不渲染** → 不展开就读不到一半对象。
4. **点左栏的行要按 `.row-name` 的 id 匹配**，不能按文本包含：行里渲染的是**原始定义**
   （`S = S_4`），而 `S₄` 是展示形态。匹不上时信息面板会**停在上一个对象**上，
   失败原因看起来像"说明没渲染"。

## 做了什么
**新增 `apps/web/src/gal/relations.ts`** —— 关系只有**两条来源，都不猜**：
1. **由来源决定**（`node.sources` + `node.opId`）：`ker f` ⊴ 定义域 · `im f` ≤ 靶群 ·
   `Z(G)`/`C_G(S)`/`N_G(H)`/`[G,G]`/`⟨S⟩`/`A∩B` ≤ 来源群 · `商` → `Q = G/N`。
2. **元素集包含**（`containment()`，**三道关**）：id 全覆盖 → `subgroupFromElementIds` 认可 →
   校验出的子群阶 = `|H|`；再拿 `findAllNormalSubgroups` + `subgroupSetKey` 判 ⊴。

三条纪律（都写成了断言）：
- **指数 1 单列成「同一」**：`[G:K] = 1` ⟺ 元素完全相同 ⟺ 同一个群
  （`ker f` 与 `闭包(G,…)` 都是 V₄；两个各自声明的 `C_6` 也一样）。
- **假阳性必须为 0**：`V₄ ≤ D₄`（core 静默丢认不得的引用→返回平凡子群）、
  `C₂ ≤ C₄`（id 是真前缀，靠乘法封闭挡住）。
- **边界写在面板上**：只列「已经建出来」的对象之间的关系（与子群 tab 标"共轭类代表"同一教训）。

面板：`InfoDock` 在**结论层与 tab 之间**插一节「关系」（类标签 + KaTeX 关系式 + 附注手算式），
`App` 把 `objects` 当 `table` 传进去；每类有上限、截掉的只说个数；反向给「派生」。

## 本轮踩到的坑（已补进 verify/README.md 的 17–20 条）
1. `subgroupFromElementIds` 对认不得的引用**静默**（返回平凡子群）→ 判包含必须另加两道关。
2. 判包含不能只看 id 前缀（`C₂` 的 `e0 e1` 是 `C₄` 的 `e0…e3` 的真子集）。
3. KaTeX 渲染后的文本要抹零宽字符再比；**附注那行是纯文本**，优先断言它。
4. PowerShell 里 `node … | Out-File -Encoding utf8` 会按 GBK 解码 → 中文乱码；
   先设 `[Console]::OutputEncoding`，或让探针用 `fs.writeFileSync` 自己落盘。
