# 2026-09-23

## 用户诉求
「一个可以优化的地方：对象栏和操作栏可以堆在一起，放在同一列」（U16）。

## 做了什么
- `App.tsx`：「对象」+「操作」包进 `.dock-col`（一个 flex 列），「信息」仍与它并排。
  整组宽度 668 → 490；`barriers.top` 随之变小 → 顶部多对象球自动左移（v3.1「只挪球，不动画布」）。
- `App.css` 新增 `.dock-col`：列 + `gap: 8px`，**封顶 `calc(100vh - 64px)`**
  （留 64px 避开左下角常驻的「数值」抽屉），`.dock-body { flex: 1 1 auto; min-height: 0 }`
  让两栏**按内容比例让高度**、缩下去变可滚动而不是被裁掉。
  单栏展开不受影响（它自己的 `max-height: min(62vh, 540px)` 先生效）→ 列表能看的行数没变小。

## 为什么这么改（判断，不是照着做）
这两栏是**同一件事的两半**（手写的定义 / 运算的产物），用户来回复查的就是它们；
并排两列会让视线来回横跳。「信息」是另一类活（"看"），留在自己一列。

  → **后** `对象 x=12,y=12` · `操作 x=12,y=98`（同列，间距 8）· `信息 x=190` · `colRight=490`。
- `tsc --noEmit` 0 错误 · 语义层 **498/498**（未触及，跑一遍留证）。

  **两栏各塞 12 行 + 1280×720 时整列不越出视口底部** · 缩下去是可滚动 · 控制台零错误。

## 取舍记录
两栏都展开时高度**按内容比例**分（内容多的让得多），不是平均分。
平均分（`flex: 1 1 0`）会把单栏展开也砍到半高——单栏是常态，不值得为对称牺牲它。
代价：两栏同时展开时行数不等（实测 8 行 vs 6 行，因为「操作」每行略高）。

## 推送
用户「先推送吧」→ `git push origin main`（走 `dangerouslyDisableSandbox`）成功：
第一次 `4a5590e..bff84be  main -> main`（把 U15 + U16 都送上去），
补记 memory 后又推了一次 `bff84be..33eb427  main -> main`。
远端核对：`git status -sb` = `## main...origin/main`（无 ahead/behind）·
`api.github.com/.../commits/main` 的 sha = 本地 `git rev-parse HEAD` = `33eb427…` ✓。

**两个工具坑（都已补进 MEMORY.md / 坑清单）**：
- **`api.github.com` 的 commits 端点有 CDN 缓存**：刚推完立刻 curl 会拿回**上一个 sha**，看着像"推送没成功"。
  带 `-H 'Cache-Control: no-cache'` 重取才对得上。
- PowerShell 一条命令里 `curl -o f.json` + `ConvertFrom-Json` 会 exit 1（PS 5.1 解析这份 JSON 失败），
  稳妥写法是**落盘后只取需要的行**（`Substring` / `Select-String`）或干脆用 `git status -sb`。
