# 可用性审计（用户视角）

> **问题不是"能不能算"，而是"用户会怎么做、那条路通不通"。**
> 这份审计换了提问方式：对每一件用户想做的事，先问**他最可能的动作是什么**（打字？点球？拖？），
> 再实测那条路。与 [TASKS.md](TASKS.md) 互补——那份是"输入视角"（这行定义能不能算），
> 这份是"**动作视角**"（用户想到这件事时，手往哪儿放）。
>
> 数据来源（都是实测，不是推理）：
> - **可点性地图**：`opsFor` / `singleOpsFor` / `multiOps` 是纯函数，直接枚举每种"选中"给出的候选
> - **任务重跑**：`docs/TASKS.md` 那份清单按输入逐条重跑（原脚本在已删的 `.tmp-verify/` 里，本次重写）
> - **真浏览器走查**：`apps/web/verify/e2e/`（交互层）
>
> 探针在 `apps/web/.tmp-probe/`（临时目录，结论在这里）。

## 0. 一句话结论

**数学能力已经不缺（55 条里 45 条能算），缺的是"路"。**

已有三个操作入口（左栏表 / 对象悬浮球 / 多对象球 ⊕）**本质是同一个模式的三种外壳**：
**先选操作，再点参数**。而用户脑子里先有的是**"把这两个凑一起"**——这条方向的路没有。
于是凡是要"关联两样东西"的意图（`f(H)`、`H ⊆ G`、`K ⊴ S₄`），一律只能打字；打不出来就卡死。

## 1. 三条路径的现状

| 路径 | 用户怎么做 | 现状 | 代价 |
|---|---|---|---|
| **打字** | 点 `✎` → 手写 `K = ker(f)` | 最可靠，覆盖全部 31 条操作 | 要记住操作名；φ 这种记号还打不出（见 §4） |
| **选操作 → 点参数** | 球 / ⊕球 → 选操作 → 点对象 | 通（`opsFor` 保证候选与可点一致） | **方向反了**；且"不上画布的对象"选不到（见 §2.3） |
| **直接操作对象** | 拖 A 到 B、拉连线 | **没有** | —— |

## 2. 可点性地图（实测：选了什么，能点到什么）

### 2.1 能点到的

| 选中 | 球里能点到 | 条数 |
|---|---|---|
| 一个群 | 共轭作用 · 正则作用 · Aut · 底集 · Z(G) · Sub · pSub · Syl · 正规子群 · [G,G] · ⟨S⟩ | 11 |
| **一条映射（点箭头）** | ker · im —— **直接铺出来，一步可点** | 2 |
| 一条作用 | 轨道 · 稳定子 · 不动点 | 3 |
| 一个集合（Ω） | 底集 · ⟨S⟩ | 2 |
| **两个对象**（⊕ 球） | × · / · 映射 · 共轭作用在 · 陪集作用 · ∩ · ∪ · \ · · · C_G · N_G | 11 |
| 一个数值 | ——（`ord` 等产数值的操作被刻意排除，用户定过"计算先不弄"） | 0 |

### 2.2 点不到的组合（有操作，但入口够不着）

| 组合 | `opsFor` 结果 | 问题 |
|---|---|---|
| **映射 + 群** | **空** | 所以 `f(H)` 这条路彻底没有——操作不存在（§4 的缺口 ⑥） |
| **映射 + 子群** | **空** | 同上 |
| 群 + 群 | × · 映射 | 合理（`G/N` 要求第二个是子群） |

### 2.3 选不到的**对象**（比"操作点不到"更隐蔽）

`subgroups`（子群集）与 `elements`（元素集）按存在层级是 `list` —— **不上画布**，
所以**用户根本选不中它们**、也就看不到它们能做什么：

| 想做的 | 数据上支持吗 | 用户实际能怎么办 |
|---|---|---|
| `Syl(G,3)` 之后要 `Ω = 底集(S)` | ✅ `opsFor([subgroups])` 给出「底集」 | **只能回去打字** ⚠️ |
| `Sub(G)` 之后要 `⟨S⟩` | ✅ 同上 | 只能回去打字 |
| 从子群集里挑一个当对象 | ✅ 信息面板有「取出为对象」 | 通（但这只在面板里） |

**这是本审计最实的一条发现**：不是操作不够，是**中间产物没有操作入口**。
`sylow → 底集 → 共轭作用在` 这条链（Sylow 演示的必经之路）**中间必须先打一行字**。

## 3. 逐意图审计

### A. 我想认识一个群

| 想做的事 | 最可能的动作 | 通吗 | 备注 |
|---|---|---|---|
| 它是什么群 / 多大 | 点节点 → 球 → **基本** | ✅ | 阶、交换、循环、单、可解、幂零、生成元 |
| **它同构于什么** | 同上，看**结论区** | ⚠️ **只说一半** | 手写的群（`G = S₄`）沉默是对的；但**构造出来的群也沉默**（见 §5） |
| 它有哪些元素 | 球 → **元素** | ✅ | 元素表含阶 / ∈Z? / 共轭类 / 类大小 / 中心化子 |
| 它有哪些子群 | 球 → **子群** | ⚠️ **语义不清** | 列表是**共轭类代表**（S₄ 只列 9 条，实际 30 个），标 `⊴` 的只有 2 条（正规子群实际 4 个） |
| 它有哪些**正规子群** | 球 → **操作** → 找「正规子群」 | ✅ 但**难找** | 操作存在且正确（S₄ → 4 个）；埋在 11 条的下拉里 |
| 它是不是单 / 可解 / 幂零 | 球 → **基本** | ✅ | 已在（TASKS.md 里记的"界面没直说"已过时） |

### B. 我想构造一个新对象

| 想做的事 | 最可能的动作 | 通吗 | 备注 |
|---|---|---|---|
| 积 / 商 / 交 / 并 / 差 / 积集 | ⊕ 球 → 选一个 → 点两个对象 | ✅ | 11 条多对象操作 |
| 由生成元造子群 `⟨…⟩` | 球 → ⟨S⟩，或打字 `闭包(G, …)` | ✅ | 元素的像对/元素记号是标量，会走补参条 |
| 造一个映射 `f: G → H` | ⊕ 球 → 映射 → 点源群 → 点靶群 → **构建器** | ✅ | 三段式；生成元的像由构建器填 |

### C. 我想把两样东西关联起来 ← **重灾区**

| 想做的事 | 最可能的动作 | 通吗 | 缺什么 |
|---|---|---|---|
| `f(H)`：子群在映射下的像 | **拖 H 到 f 上** | ❌ | 操作不存在（`opsFor([map, group])` 为空） |

| 两个对象的交 / 并 / 积 | ⊕ 球 → 选操作 → 点两个 | ✅ | 但方向反了（想的是"这两个能干嘛"） |

## 4. 输入契约的破口

| 现象 | 实测 | 性质 |
|---|---|---|
| **φ 敲不出来** | `checkName('\phi')` → `ok:false`（"名字只能用字母（含希腊字母）/ 数字 / 下划线 / 中文"）；字符 `φ` 本身合法 | 系统在模板里写 `φ = 映射(...)`，用户却敲不出——**违反"展示成什么样就得能照着敲回去"这条契约** |
| 操作名当群记号解析 | 打 `极大子群(G)` → 报"无法识别：极大子群(G)｜无法识别的群记号 …可用写法：C₁₂ · S₃ · D₄ ……" | **完全误导**：用户会以为要输群记号 |
| 关系写成 `⊆` | 打 `H ⊆ G` → 报"缺少「=」" | 用户写的是关系，系统当成漏了等号 |
| 未支持 vs 打错字 | `Burnside(A)` / `gcd(12,18)` / `φ(12)` 与"手滑打错"给**同一句**报错 | 用户分不清"没这个功能"还是"我打错了" |

## 5. 结论区的沉默规律（"K 是什么"的根因）

实测 `groupInsights` 对几个典型对象：

| 对象 | 符号 | 识别结果 | 结论条数 |
|---|---|---|---|
| `G = S_4` | `S_{4}` | `S_{4}` | 1（只有"阶"） |
| `Q = 商(G, N)` | `S_{4}/N` | `S_{3}` | **2（同构 + 阶）** ✅ |
| `K = ker(f)` | `C_{2}` | `C_{2}` | 1（只有"阶"） |
| `H = 闭包(G, r)` | `C_{4}` | `C_{4}` | 1（只有"阶"） |

**规律**：判据是"识别结果 ≠ 自身符号才说"。
- 商的符号是**构造记号**（`S₄/N`）→ 与识别结果不同 → **说话** ✅
- 核 / 像 / 子群的符号是**结构记号**（`C₂`、`C₂×C₂`）→ 与识别结果相同 → **永远沉默** ❌

而**结构记号恰恰是构造物的常态**。于是"K 是什么"这个问题，在系统里**没有地方回答**。
另外"基本"tab 的「识别」行依赖 `group.isoSymbol` —— 那是**只有从小群库建出来的群**才有的字段，
`createGroupFromSymbol` / `buildSubgroupGroup` 都没有 → **那行基本是死代码**。

## 7. 回归线的盲区（与 §6 正交的一件事）

按模块对本仓库的 `verify/` 做了一次覆盖盘点：

| 有回归守住 | 没有回归 |
|---|---|
| 求值器 · 派生图 · 布局列约束 · 数学结论 · 手算理论值表 · 五条证明模板 · 输入框 · 抽屉 · 信息面板 tab | **径向菜单（对象悬浮球）** · **拖动 / 缩放 / 格点 / 钉住**（U10 的走查脚本已不在链里） · `gal/grid.ts` / `interaction.ts` 纯函数 · `ui/MapBuilder` |

核心理念「在对象旁边完成操作」的**那条交互路径，一条断言都没有**。详见 `verify/README.md`。
