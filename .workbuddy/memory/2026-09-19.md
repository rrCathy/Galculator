## U6 收尾：箭头**形状**编码映射类型（缺口 G6 / 路线 D）+ 标签摆位（路线 E）

用户："继续推进"。选这条的理由：DIAGRAM_SPEC §1 的六条硬规范里只剩 1.4（标签字号）、
1.5（标签摆位）、1.6（箭头形状）没落地，而 1.6 同时就是体检缺口 **G6**——
"课本里 `G ↠ G/N`、`im φ ↪ H`、`G/ker φ ≅ im φ` 一眼可分"正是"像不像课本"的直接判据。

### 交付

- **`GalEdge.arrow`**（`injective` / `surjective` / `iso`）：由 `derive.ts` 的 `arrowOf()` 从
  映射属性（`isInjective` / `isSurjective`）推出，**判不出（null）时不给形状，不猜**。
- **伴生箭头按数学身份给形状**：`π` / `π₁` / `π₂` 是满射、`↪`（含 ker / im / 子群 / 稳定子）是单射、
  第一同构的 `≅` 是同构、轨道的 `=`（相等）也算同构。
- **marker 按视觉族成套生成**：`prov` / `action` / `alongside` / `map` × `head` / `surj`（双箭头）/
  `hook`（尾钩，`orient="auto-start-reverse"` 才能当 `markerStart` 用）。
- **标签摆位**：字号 = 两端对象**较小者 × 0.68**（钳 10–13，§1.4）；位置 = 沿箭头方向 **30%** 处
  再往**行进方向的左侧**让开 9——屏幕坐标下"方向 `(dx,dy)` 的左侧" = 法向 `(dy, −dx)`（§1.5）。

### 顺带修掉的两个（都是真截图/真 DOM 抓到的）

1. **marker 颜色写死**在定义里 → 蓝灰的结构伴生边配了个深色箭头。拆成按视觉族生成后，
   箭头颜色必与线色同族（走查里有逐条核对的断言）。
2. **同层水平箭头从无关对象身上穿过**：画布上同时有 `C₆ ──φ──▶ C₃` 与另一个无关的输入对象 `D₄`
   （两者同层），`D₄` 恰好排在 φ 的两端之间 → **箭头从它身上穿过去**。
   → 新增**行内相邻约束**：同层的显式映射边两端之间不许夹列组，夹着的组整体挪到行末（迭代至稳定）。
   这是竖直方向"不许跨过同列节点"在水平方向的对应物。判据仍是**边的语义**。

## U10 开放视图编辑：格点 · 缩放平移 · 拖动吸附

用户："……没看到格点，没看到视图拖动/缩放，没看到开放视图编辑（对象拖动，自动吸附到节点上，
自动改边）等功能啊"——**批评很准**：前两轮做的都是"系统内部的正确"（布局算对了、箭头形状对了），
但用户**看不见也摸不着**。这一轮全部补成看得见、可操作的。

### 交付

- **格点画出来了**（`gal/grid.ts` + 画布上的 `.grid-dot`）：列中心 × 行中心的**交点**。
  "对象落在格点上"这条硬规范从此**可见**——用户知道对象能停在哪，也知道能把它放到哪。
- **视图变换** `{k, tx, ty}`（世界 → viewBox）：滚轮**围绕指针**缩放（15%–600%）、
  空白处拖动平移、双击空白 / 工具条「适应窗口」回自动 fit；右下角常驻缩放百分比。
  `userView = null` = 跟随自动 fit；用户一旦动手，视图就归他管（加一行不会把视角弹走）。
- **拖动 → 吸附 → 钉住**（决策 ④ 落地）：拖动中显示**吸附预览环**；松手吸附到**最近的空格点**
  并**跳过已被占用的格点**；钉住**只覆盖最终坐标**（布局照常算）→ 其它节点不跳；
  边实时重画；工具条「恢复自动布局 · n」；localStorage 持久化（`?empty=1` 不读不写）。
- 吸附与格点是**纯函数**（`gal/grid.ts`），可单测。

### 三个真 bug（都是证据逼出来的，不是推理出来的）

1. **`setPointerCapture` 在 React 合成事件里只让第一次 `pointermove` 到位** →
   平移量只有应到的 **1/8**（拖 90px 只动 11px）。改成 `pointerdown` 时把
   `pointermove` / `pointerup` 挂到 **window** 上。
2. **包围盒把被钉住 / 正在拖的节点算进去** → 拖走一个节点，包围盒一变，整张图跟着重新缩放，
   **落点不再是格点**（走查里直接抓到"落点 (528,363) 不是任何格点"）。
   改成用**自动布局**的位置算包围盒。
3. **`Orb = Ω`（传递）没被纳入竖直约束** —— `isVerticalConstraint` 的标签集合只列了
   `π` / `π₁` / `π₂` / `↪`，漏了 `=` → Sylow III 的三层结构（群 → Ω → 轨道）排散。
   加进 `VERTICAL_LABELS`。

### 验证

- `tsc` 0 错误；断言 **363/363**（U0–U7 + U6b，未变）。
- 走查 **11 套 ALL PASS**，新增 `shot-u10` **16/16**：格点阵完整（= 列数 × 行数）·
  **每个节点中心精确落在格点上** · 拖动中跟着指针走 · 吸附预览环存在 · 松手落在格点上 ·
  **跳过被占用的格点** · **其它节点纹丝不动** · 自动改边 · pan 位移逐点相同 ·
  缩放比例与读数一致 · 适应窗口复位 100% · 恢复自动布局 · 空画布不残留 · 控制台零错误。
- 截图 `docs/assets/u10-drag.png`（吸附预览）、`docs/assets/u10-grid.png`（默认示范 + 格点）。

### 教训

- **"系统内部正确" ≠ "用户看得见"**。用户看不到格点，等于格点不存在；
  能过断言、能过截图对比，但用户的一句"没看到"就是最硬的验收标准。
- **写拖动类走查用例，先确认"动作能产生可观察变化"**：格点被占满时吸附会回到**原位**
  （这是算法的正确行为，不是 bug），我的第一版断言因此假红。
  加一行"拖动中位置"的打印就能一眼分辨"手势没启动"还是"吸回原位"。
- **真实鼠标事件的落点会被浮层吃掉**：`page.mouse` 按像素发事件，抽屉 / 工具条 / 输入球会截住它。
  用 `document.elementFromPoint` 先确认落点命中 `svg.canvas`，并把命中元素打印出来。

## U10 追加：同构改双向箭头 + 格点改无限网格（用户两条细节反馈）

用户："1，同态和同构的箭头可以重新设计一下。起码同构应该是双向箭头吧（同构肯定是双射的同态）
2，格点应该遍布全画布（即无限延申）"

### 1. 同构 = 双向箭头

- 形状编码改成：满射 `↠`（双箭头）· 单射 `↪`（尾钩）· **同构 = 双向箭头**（两端各一个尖）。
  从前的"同构 = 双箭头 + 尾钩"与满射、单射**都撞脸**，三种形状分不开。
- 实现：`iso` → `marker-end` 与 `marker-start` **都**挂 `-head`
  （`orient="auto-start-reverse"` 会把起点端翻向外侧）。`≅`（第一同构）与 `=`（轨道 = Ω）都走这条。
- 走查 `shot-arrows` 加了 4 条：≅ 两端都是 `-head`、且**不是** `-surj`、**不是** `-hook`（两两可分）。

### 2. 格点 = 无限延伸的规则网格

- `gal/grid.ts` 重写：从"列中心 × 行中心的交点"改成 **`GridSpec`（原点 + 步长）**：
  - `gridSpec(xs, ys)`：步长取**相邻行列间距的中位数**（粗化到 4 的倍数，有下限 48）
  - `quantize(vals, origin, step)`：把理想行列中心**量化到网格线**，并保证严格递增
  - `visibleGridPoints(box, spec)`：按**视口范围现算**可见格点（网格无限，不能预生成）
  - `snapToGrid(x, y, spec, occupied)`：跳过占用，**一圈圈向外扩**找最近的空格点
- 于是两条路径都落在格点上：自动布局**量化**、手动拖动**吸附**。
  量化顺带把不均匀的列宽差**拉平成等距**（解决了 DIAGRAM_SPEC §2.2 那条"节点宽度参与布局"）。
- 渲染：格点层按 `worldBox`（视口反算的世界矩形）生成 → **pan / zoom 到多远都铺满**。
- 顺带：自动 fit 上限 1 → **1.4**（小图不再缩在画布中央一小块）。

### 走查的两个大坑（这次花的时间最多）

1. **`page.mouse.move(x, y, { steps: n })` 不可靠**：10 步会被浏览器**合并**成 1 次 `pointermove`
   （实测 `xs=736,753`），而且在"拖一个带边的节点"这个场景里**根本没送达应用**
   （`{svg:false,node:0,ring:0}` —— 手势完全没启动）。同样的代码，③ 段拖孤立节点能过、④ 段拖带边节点不过。
   → 改法：走查里**自己派发**：pointerdown 派发到 `elementFromPoint` 命中的元素（走 React 委托路径），
   pointermove / pointerup 派发到 **window**（应用就是挂在 window 上的），每步之间等一帧。
   换过来之后立刻 ALL PASS（`move=10`、`{"svg":true,"node":1,"ring":1}`）。
2. **"铺满"的判据不能写成"顶到边界"**：网格点只落在网格线上，边缘处天然差**不到一格**。
   正确判据：**最外侧格点离边界 < 一个步长**。同理"间距等距"的容差要 ≥1（屏幕坐标取整误差）。

### 验证

- tsc 0 错误；断言 **363/363**（未变）；走查 **11 套 ALL PASS**，`shot-u10` **21/21**
  （新增：格点铺满画布、列间距等距、平移后仍铺满、格点间距按缩放比例变化）。
- 截图更新：`u10-drag.png`（吸附预览 + 三种箭头）、`u10-grid.png`（默认示范，放大 1.4 倍后清楚多了）。
