- **归纳出的六种模式**（覆盖率：60+ 条里只有「识别」组 3 条盖不住，其余全落在内）：
  1. **作用 + 三件套**（最大生成器）→ Z(G)/C(g)/N(H)/共轭类/ker/im/不动点
  2. **枚举 + 筛**（用户发现）→ 所有子群/Sylow/正规子群/极大子群
  3. **构造** → 群(记号)/⟨S⟩/积/商/映射/∩∪/陪集
  4. **迭代**（组合器，高阶）→ 导列/上·下中心列/合成列/主列

## 用户提出「类型论」视角（21:00）—— 架构的最关键一块

  |---|---|
  | 筛选 `所有正规子群` | 按属性「正规」过滤 |
  | 判定 `是否单` | 查属性「单」 |
  | 识别 `这个群是什么` | 收集**全部**属性 → 匹配小群库 |

  | 迭代 | 迭代(导出, 终止条件) | 1 |

## UI 重构规划（22:30）：核心是"在对象旁边完成操作"
- **用户十条意见归类**：缺操作面（映射 / 集合运算）· 输入重构（两块输入框 + 自动命名）· **入口重构**（径向菜单 / 查表 / 功能按钮）· 画布能力（可交互 / 拖动）· 宏。理念 = **用户应在对象旁边完成操作**。
- **核心判断**：注册表现在缺一列 —— **参数类型**。补 `OpDef.params: OpParam[]`（命名参数 + 类型）后，`opsFor(selection)` 一个纯函数同时喂三个入口（径向菜单 / 顶部工具条 / 查表面板）。"操作别扭"的根因即入口死、操作活、靠用户脑中对齐。
- **这轮侦察的 8 个关键发现**（全部来自 `@groupviz/core` v2.3.0，无需后端、无需重造）：
  1. **`buildSubgroupGroup(parent, elements, symbol, generators?) → Group`**（`algebra/semidirectDecompositions`）→ **子群可以变真群对象**，元素沿用母群 id。于是 `Z(A₄)` 出**方**节点，可 `Z(Z(G))` / `Sub(Z(G))` / `G/[G,G]`。
  2. **`resolveElement(group, ref)`**（`algebra/elementRef`）接受 id / label / value / **循环记号** → `ord(S_4,(123))` 可用；evalDef 里的 `looksLikeLiteral` hack 可退休。
  3. **结构伴生映射全现成**：`naturalProjectionMapping` · `subgroupInclusionMapping` · `directProductProjectionMapping` · `trivialMapping` → INTERACTION §4 的"操作 = 结果对象 + 结构伴生"能落地，**交换图上终于有实线箭头**。
  4. **`extendFromGenerators(source,target,Map<生成元名,像引用>) → HomomorphismMap|null`** + `verifyHomomorphism` 返回 `violation{a,b,lhs,rhs}` → 映射构建器**引擎侧已完整**，只缺一张表单。`getGeneratorElements(g)` 直接给 `{gen, el}` 对。
  5. **`listCosetStripSubgroups(group)`** → 按共轭轨道合并的子群候选（带 structure/isNormal/orbitSize/index），竖卡「所有子群」直接用它。
  6. **`getPrecomputed(group)` → `{subgroups,normalSubgroups,conjugacyClasses,center,isSimple}`** → **目录群零计算**。
  7. **`subgroupStructureSymbol(group, elementIds)`** → 子群能报名字（`C_2×C_2`/`D_4`），不必先造 Group。
  8. **`getAllSmallGroups() → SmallGroupEntry{order,index,group,precomputed}`** → 2.3 手风琴目录数据源，**自带 Group 对象**。
  - 另：core 已有 `Homomorphism{id,source,target,mapping,result?,name?}` 类型 —— 我方 `GalMap` 应改为包装它，不另立。
- **交互状态机**（新增核心，2.3+2.5 的共同要求）：`idle → selected → menu`；`idle/toolbar → pending(opId,picked[]) → 凑够 arity → 执行 或 editor`；`LayoutMode = auto | manual`。pending 时要有十字光标 + 提示条 + 已选高亮。
- **左栏两态**（解决"输入框与竖卡都在左侧"的冲突）：**输入态**（三区 + 两块输入框）/ **详情态**（竖卡，输入区折叠成一行）。单击对象进详情态，点空白返回。**不并存、不挤压** —— 用户自己说了"收起按钮后竖卡也收起"，说明竖卡是临时详情。
- **自动命名规则**：`A,B,…,Z,A₁,B₁…`，必须避开 ① 已用名 ② **注册表所有调用名**（`C`/`Z`/`C_G`/`N_G`/`Sub`/`Aut`/`Syl`/`ord`/`分解`…，否则自动生成 `Z = …` 会遮蔽操作名）③ 保留 `e`（单位元）· `p`（素数）· `G`/`H`（惯用群名留给手写）。

## 集合构造设计（22:45）：点击流与文本流是一个 AST 的两个前端
- **用户的构想**：`导入 A=A₄ → 点画布 A₄ → 竖卡元素表 → 点属性列「阶」→ 选 2 → 收入新集合 B → 画布出 B`。他自己觉得不成熟（"不如直接输入 `{x|x∈A_4,x^2=e}`"）。
- **我的判断**：两者**不是竞争关系**，是同一个 `FilterSpec` AST 的两个前端（和"三入口 = 一张表"同一个模式）：
  ```ts
  FilterSpec { domain, from: 'elements'|'subgroups', pred: AttrPred | WordPred, combine? }
  AttrPred { kind:'attr', attr, op: '='|'|'∈', value }
  WordPred { kind:'word', lhs, rhs, vars }   // x^2 = e
  ```
  **点击流不该是向导，它应该顺手把那行文本写出来给你看** —— 这正是"不如直接输入"的答案：不用二选一，点击流替你写出文本，下次你就能直接打（用户是看着语法被写出来的学会的）。这是这个功能的真正教学价值。
- **用户流程的真问题 = 它是向导**：① 一次性（生成 B 后"阶=2"的选择状态丢了，改成 3 要从零重来）② 不可见（5 步才看到东西，文本 1 步）。
- **修法**：竖卡列表做成**带分面的表格（faceted table）** —— 列头可点、就地筛选、可撤销；底部实时显示「筛选: 阶 = 2 · 3 个元素」+ **实时生成的表达式** `{x ∈ A₄ : ord(x) = 2}` + 「固化 → B」。
  **关键洞察：筛选状态不是 UI 状态，它是对象表里的一行** → 于是"可再编辑"是免费的（点 B → 竖卡回到筛选态、2 还亮着 → 改成 3 → 整图重派生），现有"对象表 = lines 的纯函数"架构直接支持，不用为它写代码。
- **「类型 × 属性」表的第二重身份**（本轮最漂亮的收敛）：架构 §4 那张表原本只是"筛的谓词库"，现在**同时是竖卡表格的列定义** —— 元素列（阶/∈Z?/共轭类/中心化子）、子群列（阶/指数/正规?/极大?/Sylow?）、群列（阶/交换?/循环?/单?/可解?/幂零?）。**一处定义，两处消费（筛选 + 展示），列随选中对象类型自动变。**
- **两条新核到的 core 能力**（实测存在）：
  1. **`parseWord(text, gens)` → `PresentationTerm[]{g,e}`**（`algebra/presentations/wordParser`）+ `group.multiply` 折叠 + 比 `identity` → **`x²=e` 这种字谓词是可做的**，不用退化成只有属性谓词。`parseRelationEquation(text, genNames)` 校验形式（必须 `f=e` 或 `f₁=f₂`），返回规范化关系或定向错误。
  2. **GroupViz 视图层已有 subset 概念**：`{ label, color, isSubgroup, isNormalSubgroup, type: 'subset'|'subgroup'|'normal-subgroup' }` + `SUBSET_COLORS`（`types/view.d.ts`）→ Galculator 的 B 就对齐成 `subset`（画布上一个圆 + 颜色）。
- **属性谓词 vs 字谓词**：分面给属性谓词（可点可选可补全，覆盖日常 90%）；表达式框收字谓词（`x²=e`、`xy=yx`、`[x,y]=e`）；`∧∨` 组合。且**属性谓词能自动翻译成字谓词**（`阶=2 ⇔ x²=e`）—— 这正是证明里"为什么等价"的一步，Sylow 模板要用。
- **与 Proof Spec 的关系（重点）**：`{x|x²=e}` 的三段（枚举→筛→固化）就是 Proof Spec 一个 `compute` step → 构造器做出来，**Sylow I 里"取全体 pᵏ 元子集 X"那一步就有可视化构造方式**；粒度 C 的"只算计数不枚举"只是同一构造器加「只计数」开关（`binomialMod` 算 |X|）。
- **阶段调整**：插入 **U5 集合构造器**，拖动→U6、宏→U7。新增待拍板第 5 条：固化出的集合**是否自动升级为群对象**（我建议：仍是 subset，但提示"这其实是个子群(V₄)，要不要升级"，由用户点 —— 系统不擅自改对象类型）。
