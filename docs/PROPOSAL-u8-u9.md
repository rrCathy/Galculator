## 2. U8 拆三批（按价值排序，不是按原条目）

### U8-a 操作表 modal ——「总共有什么、我要的那个在哪」

**要解决的问题**：用户不知道工具能做什么。现在三条入口（径向球 / ⊕ 球 / 拖拽）问的全是
"**选中了什么**，它能做什么"；而 `pointSet(5)` / `labeledSet(a,b,c)` / `smallGroup(8,3)`
这三条 op **一个对象参数都不吃**（实参全是标量或空），三条入口一条都够不着
（`CatalogDock` 的文件头就是为这件事写的）。

**形态**：一张浮层表，全量 46 条。**分组用工作台那张任务表**（`BENCH_FAMILIES` /
`BENCH_PLUS` / `BENCH_EXCLUDED`），不用 `opsByMechanism()`。

> 落地时改了分组口径（2026-10-23）：原计划按「机制」分（`atomic` / `enumerate`…），
> 实测截图一眼看出问题 —— **「共轭作用」落在「原子构造」下面**。机制是内核视角，
> 用户不这么想事。改用任务分组后，表里的位置与工作台键盘**完全一致**（同一份表），
> 完备性另由 `workbench.ts#assertPartition` 在加载时守（分组 ∪ 排除 = 全部 op）。
> 五组：造新东西 / 读它的结构 / 作用与集合 / ＋ 面板造 / 归画布 · 不进工作台。

每行显示：
- 中文名（`OP_LABEL`）+ 记号（`OpDef.notation`）+ 一句话说明（`doc`）
- 参数签名：几个对象位、几个标量位
- **当前选中状态能填到哪一步**（`opsFor(picked)` 命中 / 差几个对象）
- 点击 → `dispatchOp(op, picked)`，直接复用现成四态（pending / fill / editor / 直接执行，`App.tsx:881`）

**⚠️ 不许复活「可用操作清单」**：`INTERACTION.md:617` 已判死那东西（"已被悬浮球和多对象球取代"）。
判据差别必须写进代码注释：

| | 旧的「可用操作清单」 | 本表的「操作表」 |
|---|---|---|
| 回答 | 选中这个对象**能做什么** | 工具**一共能做什么**、我要的功能在哪 |
| 内容 | `opsFor(selection)` 过滤后的子集 | **全量**，含当前用不了的（标灰 + 说明为什么） |
| 入口 | 常驻面板 | 按需浮层，`Esc` 关 |

**不做的**：搜索框（45 条，分 6 组，扫一眼就完；加搜索是给 500 条准备的）。

### U8-b 标量候选 —— 这才是「不用记语法」

`fill` 条现在是裸 input。三种标量各给一个候选面：

| 参数档 | 现在 | 改成 |
|---|---|---|
| `element` | 手打 `r2` / `(123)` | 当前群的元素 chips（可搜、标号与循环记号同源于 `resolveElement`） |
| `prime` | 手打 `2` / `3` | 素数下拉（≤ |G| 的素数，取 `factorizeOrder` 同一份判据） |
| `int` | 手打 | 保持 input + 上下 stepper（整数是自由的，给下拉反而窄） |

**判据**：候选与 `resolveElement` **同一份**函数。列出来点下去必须真能解析 —— 这是
「菜单不撒谎」在这批的落点。

### U8-c 顶部工具条 —— 形态问题，**要你拍板**

现状：`.app` 是一个全屏画布，左上角 col（对象/操作/目录，宽 200）、右上角三件（主题/证明/画布工具）、
底部中央输入球。没有顶栏。

加通栏的代价（实测口径，不是估算）：
- 画布可用高 −40px；1024×768 下工作台展开是 78vh ≈ 599px，画布只剩 169px 可见
- `.dock-topleft` 要下移到 `top: 52`
- `layout-spec` / `dock-layout` / `narrow-docks` 三套几何断言要改

**我的倾向：先不做通栏。** 理由：U8-a 和 U8-b 做完，"不用记语法"这件事就已经解决了；
而通栏是个纯形态改动，收益是"看起来像个正经软件"，代价是画布变矮 + 三套走查重写。
真要做，也等 a/b 落地、有了操作表这个"内容"再决定它挂哪。

若你坚持要通栏，我给两个挂法（见 §6 分叉 1）。

## 3. U9 拆三批（瓶颈在语义层）

### U9-a 谓词求值器 `gal/predicate.ts`

**语法范围**（v1，落地后按实际能力修正过）：

| 形态 | 例子 | 落地 |
|---|---|---|
| 元素的幂 | `x^2`、`x^0`、`x^-1` | ✅ 快幂 + 负次取逆 |
| 乘法 | `x*x`、`x x`（并列即乘） | ✅ 但**只有同变量相乘有意义** —— 见下面第 5 条 |
| 比较 | `x^2 = e`、`x != e` | ✅ 元素比 id；纯数字标号（`S_3` 的 `12`、`C_6` 的 `3`）当元素 |
| 属性 | `ord(x) = 2` | ✅ 一参 `ord`，与主求值器两参的 `ord(G, g)` 按元数分派 |
| 逻辑 | `x^2 = e and ord(x) = 2` | ✅ `and` 优先于 `or` |
| ❌ 交换性 | `x*y = y*x` | **砍了**（见下） |
| ❌ 成员判定 | `x in Z(G)` | 砍，留 v2（要跨回主求值器 + 集合成员判定） |
| ❌ 循环记号 | `x = (12)` | 砍，v2（与括号分组的歧义在本层无法可靠消解） |

**为什么砍 `x*y = y*x`**：那个 `y` 要求在**全群**上遍历，那是量词，不是"对一个元素的筛选"。
硬塞会让"谓词"与"验证断言"变成两种语义。交换性走工作台元素表的「∈Z?」列（现成属性，不用筛）。
报错会指路，不会让用户自己猜。

**实现路线的分叉**（§6 分叉 3）：
- **A 独立求值器**：新写 ~150 行递归下降，只认上表五个形态。快、报错准、不与主求值器纠缠。
- **B 复用 `evalExpr`**：把 `x` 注入临时 objects map，让主求值器算。
  问题是主求值器**不认 `^` 当元素幂**（`^` 只出现在群记号 `C_2^4` 与元素标号 `r^4` 里），
  要改主求值器的语义 —— **风险大于收益**。

**我倾向 A。**

**门**：`|G| ≤ 144`（与 `ENUMERATION` 同口径）。超门不报错，走披露：
"这个群 720 个元素，逐元素筛选要先枚举，暂不支持"。

### U9-a·关键词表（2026-10-23 用户点名「需要考虑设置一下关键词」）

谓词是一门**新语法**，而现有语法已经占了不少字符。逐条裁定如下 ——
**三条是真冲突，必须按上下文区分；不是"让用户自己小心"。**

| 记号 | 在谓词里 | 现状谁占着 | 裁定 |
|---|---|---|---|
| `in` | 建构式的"取自"（`{x in A_4 : …}`）| ✅ 没人占（`call` 名全表里没有 `in`）| 新增，**只在花括号糖里**，不进谓词语法（见下） |
| `:` | 建构式的"使得" | ⚠️ **半直积运算符**（`C_2^2:C_3`，`splitTopLevel(canonical, ':')` @ `evalDef.ts:761`）| **靠顺序消解**：糖在 `normalizeBraces` 里把整个 `{…}` 换掉，`:` 在进半直积解析器**之前**就没了。若 `normalizeBraces` 没转（缺 `in`），`:` 才落回半直积，报错照旧 |
| `e` | 单位元 | ⚠️ **`UNIT_TOKENS = {e, id, 1}`**（`ops.ts:567`）| **复用，不加新词**。走同一个 `resolveElementLoose` |
| `ord` | 元素阶（一参）| ⚠️ **已有 op `ord(G, elem)`**（两参）| **同名复用**，按元数分派：谓词内 `ord(x)` 一参 = 阶；两参那是主求值器的 op，两者不在一层 |
| `^` | 幂 | ⚠️ 群记号（`C_2^4`）、元素标号（`r^4`）| 谓词内当幂运算。它只在**谓词字符串内部**求值，不影响外部 |
| `*` | 乘法 | ✅ 没人占（集合乘积用的是 `\cdot`）| 新增；另外**并列即乘**（`x y`）也认 |
| `=` | 相等 | ⚠️ 定义行的 `名字 = 表达式` | 定义行的 `=` 在 `commitExpr` 那层**先被拆掉**，不进 `evalExpr`。谓词里的 `=` 只比较元素 |
| `!=` | 不等 | ✅ | 新增 |
| `and` / `or` | 合取 / 析取 | ✅ | 新增，优先级 `and` > `or`。分面表格叠两个属性要用 |
| **单字母变量** | `x` | ⚠️ **`resolveElementLoose` 把单字母当生成元**（循环群里 `r` 就是 `r`）| **绑定变量遮蔽一切**：先查变量表，查不到才落回元素解析。判据一句话：谓词里 `x` 永远是变量，不是元素 |

**明确不做的四件事**（防以后翻旧账）：

1. **不做 `where` 别名。** `:` 与 `where` 双写法会逼用户猜"哪个才是正解" —— 与
   `labeledSet(5)` 那条"两种读法都通时不许猜"同一个判据。只给 `:`。
2. **`in` 不进谓词语法。** `{x in A_4 : x^2 = e}` 里的 `in` 是**建构式的一部分**
   （"x 取自 A_4"），不是谓词里的成员判定运算符。v1 不做 `x in Z(G)` ——
   它要跨回主求值器 + 集合成员判定，留给 v2。分面表格的「∈Z?」列**不用谓词**，
   直接勾选（它只有 v/x 两值，勾选就够了）。
3. **不做 `not` / `forall` / `exists`。** 否定的需要由 `!=` 与 `and` 覆盖；
   量词是证明层的活（`PROOF_SPEC`），不是筛选条件。
4. **`filter` 的中文名是「筛选」**（`OP_LABEL`），但**解析器只认 `filter`** ——
   与 U54「操作名统一 ASCII、中文只做显示名」一致。

**一处对用户交代的话**（报错文案）：`{x in A_4 : x^2 = e}` 里 `x` 用了几次都行，
但它**必须**与 `in` 左边那个字母**同名**。写成 `{x in A_4 : y^2 = e}` 要报
「变量名对不上：左边是 x，条件里是 y」—— 别让它静默筛出空集。

### U9-b 新 op `filter` + 集合建构式语法糖

```
filter(S, x, x^2 = e)          ← 一等公民（可组合、可进证明层）
{x in S : x^2 = e}             ← 糖，规范化层转成上面那条
```

**三个技术点**：

1. **`ParamType` 新增 `expr` 档**（标量档，原样文本）。**这条路已经实测通了**：
   - `evalExpr('filter(A_4, x, x^2 = e)')` 现在报的是「**没有名为「filter」的操作**」——
     说明 `splitCall` **已经把它正确切成 3 个参数**，只差注册表里没这条 op；
   - `resolveArg` 的兜底就是 `{ kind:'literal', text: s }`（`evalDef.ts:301`），
     谓词原样到达 `run`；
   - 谓词文本过 `normalizeExpr(p, false)` **一字不改**（实测 5 条：`x^2 = e` / `x != e` /
     `ord(x) = 2` / `x*y = y*x` / `x^{2} = e` 全部原样，`^` 前缀豁免正好护住上标写法）。
   - 只需保证谓词里**不许有顶层逗号**（v1 禁止，报错说清），否则会被当第四个参数切开。
2. **糖放在 `normalizeBraces` 之前**：`{…}` 的判据从"一律转 labeledSet"改成
   "含顶层 `:` 且左边是 `<var> in <expr>` ⇒ 转 `filter`，否则照旧转 `labeledSet`"。
   `{a, b, c}` 与 `{x in A_4 : …}` 两条腿都留。
3. **结果类型：`elements`，不是 `set`**（§6 分叉 4）。
   `elements` 有母群、成员带元素 id ⇒ 能直接喂 `closure` / `conjOn` / `asSet` / 造结构。
   `set` 只能当 Ω。**场景 3（`S_3` 去掉 `(12)`）要的是前者。**

**顺手补的披露**：筛出 0 个元素时**不报错** —— "空集"是合法结果，也是最常见的教学结论
（`A_4` 里 `x^2 = e` 有 4 个；而 `ord(x) = 6` 是空集 —— 空集也是答案）。

### U9-c 分面表格 UI

工作台「元素」节（`InfoDock` 的 `elements` tab，现在渲染 `ElementsTable`）：

- 行首加**勾选列**（多选）
- 表头属性列变**分段按钮**：点「阶」列的 `2` ⇒ 选中所有阶为 2 的行
- 底部一条：「造集合（n 个）」+「按属性写条件」输入框（点属性分段时自动填成 `ord(x) = 2`）
- 确认 ⇒ 落一行定义（`S = {a, b}` 或 `S = filter(G, x, ord(x) = 2)`），画布长节点

**与 U9-b 的关系**：表格点选产出的**是同一批 op 的调用**，不是另一条路。
点勾选 ⇒ 具体元素 `{…}`；点属性 ⇒ `filter(…)`。用户想改就改那一行 —— 这就是"固化/再编辑"。

## 7. 风险（提前说清，免得做完翻旧账）

1. **操作表与三条既有入口的分工**：它是"发现"，不是"操作"。若走查里两者列出的东西重叠，
   说明判据错了 —— 操作表必须**含当前用不了的**（标灰 + 原因），否则它就退化成第四个球。
2. **`{…}` 语法的兼容面**：`normalizeBraces` 被 Ω 实参、元素下标三处依赖
   （`_x` / `^x` / `\x` 三种前缀豁免）。改判据必须保住这三条豁免，走查 `point-set` 会抓。
3. **`ElementsTable` 加列**：`workbench.mjs` 98 条里有对表头/行数的断言，改表头要同步。
4. **谓词求值的崩溃面**：core 在"元素表示对不上"时会**直接抛**（`N_G` 那次的教训）。
   谓词求值必须自己 try/catch，报"这个条件在某元素上算不了"而不是整页崩。
