# 提案：主界面 UI/UX 优化 —— 栏目与按钮的形态、位置

> 2026-10-20 · 状态：**待裁定** · 依据：真机截图（1440×900 / 1280×800 / 1024×768，浅色 + 深色）+ 几何量测（`.tmp-shot/`）。
> 本文只谈**版面与形态**，不改数学层、不改交互判据、不动 `App#onNodeClick` 那条唯一入口。

---

## 0. 结论先行

主界面不缺功能，缺**一层统一的"栏"**。现在 9 个浮层各写各的宽度、高度、圆角、停位，于是长出三类病：

1. **几何硬伤**——球压左栏、台压左栏、窄窗把明细挤没；
2. **形态不齐**——三个抽屉三种宽度、两颗一模一样的黑球、右上角三件三种高度；
3. **工作台内部三列并行**——对象槽 96 + 键盘 340 + 竖导航 86，正文只剩 548px（1140 里 48%）。

建议拆四档施工：**A 几何修正（不破走查）→ B 栏目合并 → C 工作台重排 → D 形态统一**。A 档今天就能做，B/C 要先拍板 §3 的五个分叉。

## 2. 方案

### A 档 · 几何修正（不改 DOM，36 套走查应能全绿）

| 条目 | 做法 | 验收 |
|---|---|---|
| A1 | 球停位改**右下停**（`right: 12`，两球竖排于数值栏上方）；不再贴左栏 | 球矩形与 `.dock-topleft` 不相交 |
| A2 | 台宽改 `min(1240px, calc(100vw - var(--dock-w) - 48px))`，`left: max(50%, calc(var(--dock-w) + 24px))`；`--dock-w` 由 App 量 `.dock-topleft` 宽度写入 | 台左缘 ≥ 栏右缘 + 12，三种窗口都不相交 |
| A3 | 空态分家：无对象 → 「还没有对象」；**有对象无焦点 → 「还没有选中对象」+ 对象列表**（复用 stage 数据，点一行即聚焦） | 文案断言 + 有对象时不再出现"还没有对象" |
| A4 | ≤1080：键盘默认折叠为一行「键盘 ▾」，明细优先；台高 68vh → 76vh | 1024×768 明细可视 ≥ 260px |

### B 档 · 栏目合并（会改 DOM）

| 条目 | 做法 | 收益 |
|---|---|---|
| B1 | 左栏三抽屉 → **一栏三段**（对象 / 操作 / 目录），头统一 40 高、宽统一 200，手风琴互斥（同时只开一段，默认只开对象） | 宽度不再跳；总高可控；"同一件事的两半"落在同一张卡里 |
| B2 | 数值抽屉**默认收起**，有数字时角标提示、拖入数字时自动展开 | 左下 170×119 还给画布 |
| B3 | 右上统一 32 高、8 间距；主题按钮改**图标 + 当前态**（☀/☾），title 写全 | 三件成组、不再跳基线 |
| B4 | 输入球改**胶囊**（`✎ 输入`，88×32），多对象球保留圆 `+` 并加 title | 两颗球不再撞脸 |

> ⚠️ 选择器不许改名：`.composer-orb` 被 **32 套**走查引用、`.dock-topleft` 19 套、`.bench-toggle` 12 套。形态可以换，**class 名与 data-* 保持**，否则半个走查库要重写。

### C 档 · 工作台重排（需拍板 §3）

| 条目 | 做法 | 收益 |
|---|---|---|
| C1 | 对象槽 96 竖列 → **屏下横条**（高 36，chips 横排可滚）；或保留竖列但仅在 ≥4 对象时出现 | 正文 +96px |
| C2 | 显示屏 60 → 56，右侧补一行元信息（阶 · 交换 · 单）；删掉明细里重复的「阶」行 | 少一行冗余、屏不再空半截 |
| C3 | 竖导航 86 → **横排 tab**（高 34，下划线选中），与 ≤1080 的形态统一 | 正文 +98px（548 → 646） |
| C4 | 键面加中文副标（10px）：`→ 映射` `× 直积` `∩ 交` `N_G 正规化子`；重名的 `↷` 拆成「共轭作用 / 左作用」 | 27 键可读，不再靠猜 |
| C5 | 台面玻璃不透明度 +0.05，或正文页加实底 | 背后节点不透字 |

### D 档 · 收尾（可选）

- D1：`＋ 导入对象` 与「目录」目前是**两份实现**（`Workbench` 的 plus 面板 vs `CatalogDock`），抽成同一个组件。
- D2：显示屏副行给 `A = S₄`，让"左栏的 A"和"台里的 S₄"当场对上。

## 3. 需要你拍板的五个分叉

| # | 分叉 | 选项 1 | 选项 2 | 我的倾向 |

## 5. 验收口径（建议写进走查，不靠肉眼）

1. 几何：`.dock-topleft` 与 `.bench`、`.composer-orb`、`.orb` **两两不相交**（三档窗口）；
2. 空态：有对象无焦点时，页面文本**不含**「还没有对象」，且能一键聚焦；
3. 阅读：1024×768 下 `.bench-page` 可视高度 ≥ 260px；
4. 形态：`.theme-toggle` / `.settings-btn` / 证明胶囊三件高度差 ≤ 2px；
5. 正文：1440 下 `.bench-page` 宽度 ≥ 620px。

---

## 6. 不做的事（避免翻旧账）

- 不把工作台改成侧栏（§5 已定：画布铺满、抽屉浮在上面）；
- 不让画布给抽屉让位（v3.1 定死）；
- 不恢复右下工具条（W1.6 已删）；
- 不动 `App#onNodeClick` 与 `canPick` 判据（形态层的改动不许碰语义层）。

## 7. 落地实况（2026-10-20）

> 用户「没啥问题，先这么优化吧」⇒ 按 §2 施工。下面按档记**实际做了什么**、**改了什么契约**。

### A 档 · 几何（全做）

| 条目 | 落地 |
|---|---|
| A1 | 两球改**右下停**：`ComposerOrb` 去掉 `dockLeft`，台升起时走 `dockRight`；对象球 `dockX = containerW - 25`、`dockY = containerH - 96`（与输入球叠成一列，仍与台高解绑）。环与操作面板镜像到**左侧**（`angleAtDock` = 90°→270°，面板 `left: dockX-12-252`）。`.app.bench-open .composer-orb` 的"抬到台顶"规则删除 |
| A2 | `.bench` 改 `--bench-w` + `left: calc(dock-w + 12 + 剩余区居中)`；`--dock-w` 由 App 把 `barriers.top`（= `.dock-topleft` 右缘）写进根节点。栏 200 时 1440 下台 = 262..1402 |
| A3 | 空态分家：无对象 → 「还没有对象」；有对象无焦点 → 「还没有选中对象」+ 对象 chips（点一下 = `onPick` = `App#onNodeClick`） |
| A4 | ≤1080：台高 68vh → **78vh**；新增「键盘」开关（默认收起，见 `padOpen`）；左列 `max-height: 44%` 自己滚 |

### B 档 · 栏目（B1 换了做法）

| 条目 | 落地 |
|---|---|
| B1 | **不拆 DOM**：三个 `.dock` 保留，靠 CSS 把三张卡**接成一条栏**（`.dock-col` 承担边框/圆角/阴影，节透明无边框，节间由下一节的头画分隔线），宽度统一 **200**。⚠️ 原方案写的是"一栏三段切换"，实现时改成"一栏三节可同时展开"——保住 `对象 + 操作` 同时可见，也保住 19 套按 `.dock-toggle:has-text()` 找按钮的走查 |
| B2 | 数值抽屉默认收起；**第一次出现数字时自动拉开一次**（`numericHadContent` ref） |
| B3 | 右上三件统一 32 高、`align-items: center`；主题按钮改**图标 + 当前态**（太阳=浅色 / 月亮=深色），title 写全 |
| B4 | 输入球 → 「＋ 输入定义」胶囊（`.orb-center` 类名保留，32 套走查照旧点得到） |

### C 档 · 工作台（全做，另有两处计划外）

| 条目 | 落地 |
|---|---|
| C1 | 对象槽 96px 竖列 → **满宽横条**（`.bench-stage` 高 28、chips 横排横滚）。为此新增 `.bench-cols` 容器包住左右两列（`.bench-body` 改列方向：横条 + 两列） |
| C2 | 显示屏标题行右端加「阶 24」；**删掉明细里重复的「阶」行**（`InfoDock` 基本节） |
| C3 | 竖导航 86px → **横排 tab**（下划线选中）；正文 548 → **756**（1440） |
| C4 | 键面加中文副标（`menuLabel(op)` = `OP_LABEL` 同一份），键高 36 → 46 |
| C5 | `--glass` 浅 0.62 → 0.82、深 0.72 → 0.88（背后节点的字不再透上来） |
| 计划外 ① | `＋ 导入对象` 从"左列底部"挪到**标题条右端**：键面加副标后左列会滚，主按钮不能藏在滚动区 |
| 计划外 ② | 对象槽横条当初写 `flex: 1 1 100%` 在列方向父级里变成"占满台高"，两列被顶到台底（已修，记在 CSS 注释里） |

### 契约变更（走查同步）

| 套件 | 改动 |
|---|---|
| `dock-layout.mjs` | 三节之间 **gap 8 → 0**；列高 = 三节之和（±2 边框）；**收起态宽度不再变窄**（与展开同宽 200，这是"一条栏"的有意契约） |
| `relation-ops.mjs` | 「阶」从明细行搬到屏幕角标 ⇒ `infoState()` 多读 `.bench-screen-order`，两条断言接受"行或角标" |

### 没做

- **D1 抽公共「新建对象」面板**：`NewObjectForms` 本就共用（集合/结构），重复的只有**群库列表**（`＋` 面板 vs 目录）—— 属于纯重构，这一批没动。
- **D2 显示屏副行给 `A = S₄`**：`ml.sub` 本来在有 `def` 时就会显示，S₄ 这种"名字=定义"的对象没有副行，不算缺口。
