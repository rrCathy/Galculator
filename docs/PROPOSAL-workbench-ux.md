## 1. 方案一 · 纵向精修（改动可控）

> **主张**：五段不动，逐处放对位置——键盘成块、状态归一、明细不重复。

**用户看得见的变化**：

1. **焦点行**（新，替代旧显示条）：左边数学身份（大）+ 识别副行；中间一枚**状态胶囊**——
   正常时说「阶 8 = 2³ · 非交换」，pending 时变琥珀色说「② 待选：B（群）· Esc 取消」；
   右边 [＋ 导入对象] 主按钮 + [⋯]。**全应用只此一处说状态。**
2. **台面并入标题栏**：chips 排在「⌃ 工作台」右侧一条，不再单独占行。
3. **键盘成块**：按"动词"分五块 —— 造新东西(6) / 读它的结构(5) / 子群与正规(7) /
   作用与轨道(4) / 集合运算(5)，块内成网格、块间留白；「× ⋊ / ⟨⟩」从"群与分解"挪进"造新东西"，
   两键残缺行消失；参数数角标改小胶囊。
4. **明细区去重**：删掉重复的"识别"卡（身份只在上方焦点行说一次），tabs 直接铺数据。
5. **`＋` 面板改整宽三段手风琴**：常用群（open，chip 带「阶」角标）· 群库（折起，
   搜索框常开，展开才是按阶网格）· 自定义（三张卡片：图标 + 名称 + 示例 + 输入 + 「造」）。
6. **pending 引导归一**：状态胶囊 + 明细区槽位候选（键盘保持可点 = 随时换主意）。

**代价**：L2 为主 + L3 两处（焦点行/台面并栏、`＋` 面板）；`workbench.mjs` 的
显示条、`＋`、槽位三组场景要按新 DOM 重写。

## 2. 方案二 · 横排计算器（形态一步到位）

> **主张**：左键盘右明细——真计算器的摆法。**显示屏永远说清"正在算什么"，读的区域永远不动。**

**用户看得见的变化**：

1. **左列（398px）**：显示屏（身份 + 识别 + 状态）→ 键盘三块（造新 / 读结构与子群 / 作用与集合，
   27 键）→ 底部整宽 [＋ 导入对象]。
2. **右列**：明细大阅读区（tabs + 平铺行）——按键盘、翻台面时右列**纹丝不动**，
   操作和阅读不再争一块屏。
3. **`＋` 按下 = 左列整列变手风琴**（键盘退场）：常用 / 群库 / 自定义三段，
   右列保持可见——**边造边看**。
4. **pending 用计算器语言**：显示屏写算式「`D₄ × ▢ = …`」，左列键区变候选列表，
   点一下填空。读数与填空在同一列完成。
5. 台面 chips 同样并到标题栏右侧。

**代价**：L3 为主（工作台内部布局重排）；`workbench.mjs` 改动面比方案一大；
好处是形态与"计算器"隐喻完全对齐，明细区获得真正的阅读宽度。

## 4. 建议怎么选

- **想小步快跑：选方案一。** 其中三项可以各自独立验收——
  ① 焦点行状态归一并栏；② 键盘块化（含「造新东西」挪 3 键）；③ `＋` 面板手风琴 + 预览。
  走查每项改一组场景，风险分散。
- **想一次到位：选方案二。** 它是同套内容换骨架（方案一的焦点行 = 它的显示屏），
  形态最贴"计算器"，代价是走查重写面大一档。
- 细节页的三个推荐项（微名键帽、`＋` 预览、引导归一）**可并入任一方案**，不绑定。
- 无论选哪个，**顺手把旧账修了**：`＋` 面板点外 / Esc 关闭。
