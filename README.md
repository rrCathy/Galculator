# Galculator

群论计算器：把**计算**和**证明**放在同一张可操作的交换图上。

你敲一行群论定义，画布上长出对象；你点一个对象做运算，运算本身就变成图上的箭头。
Desmos 把函数变成曲线，这里把群论计算变成交换图。

![默认示范：Sylow III 的完整故事](docs/assets/u11-default-sylow.png)

## 为什么做

- 群论抽象、门槛高。Sylow 定理人人会背，但很少有人真正**看见**论证怎么展开。
- Desmos / GeoGebra 覆盖了实函数与几何，**群论没有对应的计算器**。

## 定位

**群论计算器，不是又一个群论可视化工具。**它回答的是"这个群论问题**算出来是什么**"；
画布是计算的**操作台**，不是输出端口 —— 你在图上点对象、选运算，运算本身变成图的一部分。

| 参照 | 关系 |
|---|---|
| Desmos / GeoGebra | 借它的"交互的即时反馈"。**但画布的角色相反**：它们是输出，这里的画布是操作台 |
| Group Explorer | **不是同一件事**：它把群**画**出来（凯莱图 / 乘法表），这里把群论**算**出来；它的可视化约定只在"需要展示某个产物"时作参照 |
| Lean / Coq | **不碰**。形式化证明是另一件事；这里做的是演示性证明 —— 模板人工写，机器在具体群上实例化并画出来 |

因此：**引擎（`@groupviz/react`）的 10 个可视化 Scene 一个都不接**（U51 定案）——
只复用 `@groupviz/core`（纯算法层）作计算内核的底座。完整方向定案见
[docs/ROADMAP.md](docs/ROADMAP.md) 开头的「定位」。

目标场景：**用群作用证明 Sylow 定理**，一步步走完，画布跟着长出证明图。

## 快速开始

```bash
pnpm install
pnpm dev          # → http://127.0.0.1:5273
```

打开就有一张默认示范（Sylow III 的完整故事）。想从空白开始：`http://127.0.0.1:5273/?empty=1`。

**三步上手**：在画面正下方的 `✎` 输入球里敲

```
G = S_4
```

回车，画布上出现 `S_4`。再敲 `A = A_4`。然后从 `A` 拖到 `G` 松手 —— 工具自己判断这两个群之间能做什么。

## 能写什么

输入框是「名字 + 表达式」两块：名字留空会**自动命名**，表达式**边打边校验**（合法就当场说会产出什么，非法给红字与定向提示）。
文本一律 **ASCII**（`S_4` 而不是 `S₄`，`\varphi` 而不是 `φ`）—— 敲不出来的字符会被拦下并给出可照抄的改法；显示侧走 KaTeX 真排版。

| 输入 | 机制 | 产物 |
|---|---|---|
| `G = S_4` · `G = D_4` · `G = A_4` | 记号建群（**一个记号一个群**）| 群节点 |
| `P = G x H` · `P = C_2 x C_2` · `Q = G / Z` | 原子构造（直积 / 商群） | 群节点 + π / π₁π₂ 伴生箭头 |
| `N : H`（中缀）· `semidirectProduct(N, H)` | 原子构造（半直积） | 群节点（`⋊` 的作用欠定时**列候选**，不替你挑） |
| `A = conjAction(G)` · `A = conjOn(G, Omega)` · `A = cosetAction(G, H)` · `A = leftAction(G)` | 原子构造（作用） | 作用对象 + 作用线（可点选，直接铺出轨道 / 稳定子 / **轨道条数**）|
| `A = customAction(G, 4, a -> (1 2 3 4))` | 原子构造（自定义作用） | 作用对象（逐个生成元给像，编辑器里「边填边看」） |
| `Z = Z(G)` · `Cg = commutator(G)` · `N_G(G, H)` · `C_G(G, x)` · `Inn(G)` | 作用导出（子群） | 群节点（子群是**真群对象**，所以 `Z(Z(G))` 合法） |
| `I = A \cap B` · `∪` · `\setminus` · `\cdot` | 集合运算 | 集合节点（∩ 与 · 若结果是子群，升级为群对象） |
| `V = pointSet(5)` · `L = labeledSet(a, b, c)` · `S = asSet(Syl(G, 3))` | 原子构造（集合） | 集合节点（被作用的舞台 Ω —— 凭空造任意阶集合） |
| `K = smallGroup(16, 3)`（编号 1 起，同 GAP） | 原子构造（小群表） | 群节点（内嵌 1–31 阶 **93 个群**的乘法表 —— 表里没有别的入口的群在这里也能拿到） |
| `R = A \subseteq B` · `R = A \cong B` · `contains(H, G)` | 声明关系 | 画布上一条可点选的 `⊴` / `↪` / `≅` 边（正规性由工具判，不由你声明） |
| `K = <J>` · `K = closure(G, r2)` | 迭代（闭包） | 群节点 |

> **为什么 `C_2 x C_2` 不在第一行**：它虽然长得像个记号，但内核把它归约成
> `directProduct(C_2, C_2)` —— 于是它落在**「操作」抽屉**而不是「对象」抽屉里
> （F6，2026-10-05 实测：`origin = derived` / `opId = directProduct`，手打也如此）。
> 记号建群那一行只放**真正一个记号一个群**的（`S_4` / `D_4` / `A_4` / `GL(2,3)`…）。
| `f = map(G, H, r -> e, s -> s)` | 原子构造（同态） | 实线箭头（不占节点，**可点选** → 环绕出 `ker` / `im`） |
| `O = orbits(A, x)` · `stabilizer(A, x)` · `fix(A)` · `burnside(A)` | 作用导出 / Burnside | 集合节点 / 数值（Burnside 平均式当场对账） |
| `S = Sub(G)` · `pSub(G, 2)` · `Syl(G, 2)` · `maximalSubgroups(G)` · `normalSubgroups(G)` | 枚举 + 筛 | 子群集（每一项都能「取出为对象」） |
| `ord(G, (123))` · `C(12, 4)` · `Cmod(12, 4, 2)` · `gcd(12, 18)` · `lcm(4, 6)` · `phi(12)` · `factor(24)` · `Aut(G)` | 属性 / 算术 | 数值 / 群（左下数值区） |

元素参数走 core 的 `resolveElement`：`id` / `label` / 循环记号都命中，所以 `ord(S_4, (123))` 合法。
**操作名一律 ASCII 英文**（`directProduct` / `customAction` / `maximalSubgroups` …），菜单标签就是从名字派生的，所以「菜单上看到的」就是「敲得出来的」。
全部 45 条操作在 [`apps/web/src/gal/ops.ts`](apps/web/src/gal/ops.ts) 的注册表里（每条声明机制、命名参数与类型，菜单由 `opsFor(selection)` 派生）。
`smallGroup(n, i)` 的编号是 **GAP 的标准编号**（`SmallGroup(8,3) ≅ D₈`、`SmallGroup(24,12) ≅ S₄`），与信息面板里那条「识别」印出的坐标是同一个口径 —— 照抄印出来的坐标就能拿回同一个群。

## 界面上有什么

- **正下方 `✎` 输入球**：唯一的文本入口；点出来的操作也会被编回一行文本走同一个求值器，所以「点出来的」和「打出来的」行为必然一致。
- **左上四个抽屉**：`对象`（手写的定义）· `操作`（运算产物）· `目录`（从库里挑）同列上下，`信息` 另一列 —— 信息面板只回答"这个对象是什么"：**结论**（识别 / 同构 / 第一同构定理）＋ `基本` / `元素` / `共轭类` / `子群` **四个可折叠分区**（单开、默认全收，标题行带一行摘要：阶 / 元素个数 / 共轭类数 / 子群同构类数）。结论那句"答案"是面板里最大的一档（20px），其余按对象名 / 分区标题 / 附注依次收小 —— 一眼先看到结果。
- **`目录` 抽屉**（U56）：**凭空造**东西的入口 —— 上半是**集合**（造 `pointSet(5)` / 按标号造 `labeledSet(a, b, c)`），下半是**群手风琴**（1–31 阶 **93 个群**按阶分组，点一个名字就落成一行 `G = smallGroup(8, 3)`，与手敲完全同源）。这两类东西的实参全是**标量**，所以三个手势入口一个都够不着 —— 它们只能从这儿进。
- **贴底工作台**（工作台 v2.2，2026-10-08）：一台半透明玻璃"计算器"，**也是唯一的信息面**（原左上「信息」面板已并入）—— **显示屏**写数学身份（`A₄`，不是 `smallGroup(12, 3)`；定义降为脚注）+ 值类型徽标、**对象槽**记住碰过的对象（点 chip 切焦点，`x` 拿下不删对象）、**符号键盘**随焦点变（群 27 枚键 / 集合只剩"造结构"，键面走 KaTeX）、右列**明细区**= 左缘**竖排节导航**（基本 / 元素 / 共轭类 / 子群…，标签只写名字）+ 内容；集合 / 子群集 / 作用 / 映射 / 结构边的信息全部并在这里（结构箭头的「这条箭头」、映射的「元素送到哪里去」都在）。pending 时**槽位区**在台内凑参数（升起时画布节点被盖住，槽位是唯一通路）、`＋` 导入对象（常见群 chips + 93 群库，**标准群记号 KaTeX 渲染**——`C₅:C₄`、`SL(2,3)` 正体）、**编辑器卡片嵌在右列**（工作台没开时进编辑器自动升起）。点画布对象 / 点对象行 / 球菜单「元素 · 子群」都会**自动升起工作台**。键盘发起的操作与球菜单 / 拖拽 / 手敲走**同一条求值路**。
- **点画布上的节点** → 冒出一颗悬浮球。群节点环绕「基本 / 元素 / 子群 / 操作」（前三个是「看」，打开面板并展开对应分区）；集合节点环绕「信息 / 被作用 / …」（见下条）。
- **造一个群作用**（U57）：**四条路都通** —— ① 点**群**节点的球 →「操作」→ `customAction`（最直接）；② 点**集合**节点的球 →「被作用」→ 再点一个群（Ω 已经指好了，编辑器里那一格就是它）；③ 画布上方 **⊕ 球** → `customAction`；④ 把群**拖到**集合上。四条落到**同一个** op、同一份内核；编辑器里 Ω 那一格会列出画布上已有的集合，点一下就选它。
- **作用的作用点集 Ω**（U58）：那一格**也能在画布上点**（⊕ 球里走到第 2 位，「可选：Omega …… 不选就进编辑器填」）；能当 Ω 的东西有四种 —— 集合（`pointSet(5)` / `labeledSet(a, b, c)` / `asSet(S)`）、元素集、**子群集**（`Syl(S₄, 3)` / `Sub(A₄)` 直接用，不必先 `asSet`）、群（当它的底集读）。标号不是数字时（子群集正是这样），编辑器会按 **`1 <234> , 2 <123> , …`** 把点号点名列出来 —— 填像写的是点号，你总得看得出第 3 个点是哪个。
- **作用的信息**：`核`（忠实吗 —— 共轭作用的核就是 Z(G)、左正则作用是 Cayley）＋ **「元素送到哪里去」** 那张表（每个元素映成 Ω 上的哪个置换，与映射那张表同一个形状）。
- **拖拽连线**：从 A 拖到 B 松手，列出这两个对象能做的事；唯一候选直接执行。
- **右上证明面板**：5 条定理模板（Sylow I / II / III · 轨道-稳定子 · 第一同构），逐步演示 —— 「下一步」把这一步的定义真的写进定义表，画布跟着长。
- **右下工具条**：缩放 / 适应窗口 / 恢复自动布局 / 视图快照（把整张图存成一段文本带走）/ 清空画布。画布自动保存，刷新还在。

## 画布上的规则

三条硬规范，不是「尽量对齐」：

- **形状 = 类型**：群是一块淡底上的符号，集合是圆。
- **颜色 = 来源**：蓝 = 手写输入，紫 = 运算产物，绿 = 作用。
- **箭头形状 = 映射类型**：`↠` 满射双箭头，`↪` 单射尾钩，`≅` 两端尖。判不出就不猜，退回普通箭头。

水平箭头同高、垂直箭头同列，对象落在格点上（格点画得出来，能拖能吸附）。细则见 [docs/DIAGRAM_SPEC.md](docs/DIAGRAM_SPEC.md)。

```

  src/gal/               纯逻辑层，无 React，可单测

    build.ts             定义行 → 对象表

  src/ui/                画布与面板：CanvasView（SVG 交换图）/ 四个抽屉 + 数值区 / 输入球与悬浮球 / 证明面板 / 映射构建器 / 工作台（玻璃计算器）
  verify/                回归线（入库，是资产不是临时物）
    suites/              语义层断言（27 组，纯逻辑）
```

## 状态与边界

**已落地**：U0–U59 的界面与交互迭代、M0–M3 里程碑（含 5 条定理模板逐步演示）、工作台 v2.2"玻璃计算器 + 信息面合一"（2026-10-08）。逐批的取舍与验收账在 [docs/HISTORY.md](docs/HISTORY.md)，本文件不复述。

**还没有的**：Cayley 定理的模板（缺「忠实作用 ⇒ 嵌入」在图上的落点）· 集合的**描述式**构造（分面表格 + 属性谓词 `{x in A_4 : x^2 = e}`；凭空造点集与导入 1–31 阶小群表已经有了）· 宏 · 后端计算栈（GAP 推迟，目前全靠 `@groupviz/core` 的前端原语）。

**已知边界**（有意为之，不是待修的 bug）：

- `image(f, H)` 在 H 有多个嵌入时**不自动翻译** —— `f(H)` 是一个具体的子群，「取哪个嵌入的像」说不准。
- 大群有硬上限（子群枚举 / 结构节 `|G| ≤ 60`）。超限时**明说「没算」**，不会拿一个错答案糊过去。
- 正规性跳不过元素：`H ⊴ G` 问的是「G 里那个具体拷贝稳不稳」，裸群说不出是哪一个 —— 这时如实回「未判定」。
