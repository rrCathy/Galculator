## 定位：群论计算器，不是可视化工具

> **这是全仓库的方向定案。** U51（2026-10-02）用户拍板，2026-10-04 从"某一批的取舍"
> 升格写进规划。**其余文档（README / ARCHITECTURE / PROOF_SPEC / INTERACTION）里
> 凡与本节冲突的表述，一律以本节为准。**

**Galculator 是一个群论计算器。**它要回答的是"这个群论问题**算出来是什么**"——
敲一个记号或表达式，得到答案（阶 / 结构 / 子群 / 同态 / 轨道 / 计数…），
并且**答案的推导链条可见、可改、可复用**。

**画布是计算的操作台，不是输出端口。**这是与参考产品的根本差别：

| | Desmos / GeoGebra / Group Explorer | Galculator |
|---|---|---|
| 画布是什么 | **输出**：把算好的东西画出来 | **操作台**：在图上点对象、选运算 |
| 用户做什么 | 打字 → 看图 | 点对象 → 让运算长出图 |
| 图的角色 | 结果 | 过程本身（对象是输入与产物，箭头是运算）|

**因此三件事被钉死**：

- **不接引擎的可视化层。** `@groupviz/react` 的 10 个 Scene（`CayleyView` / `CycleView` /
  `TableView` / `ActionScene` / `LatticeScene` …）**一个都不接**。凯莱图、乘法表这类
  "把群画出来"的产物**不是产品目标**；需要时由自研交换图画布承担，或按需另起。
- **引擎只当算法层用。** `@groupviz/core`（纯算法，零 DOM）是计算内核的底座；
  `@groupviz/react` 只借它的 `theme.css`。
- **规划不再排"可视化"的账。** 任何"接入 Scene / 联动 GVL / 自绘 XX 视图"的条目
  从待办里移除（历史批次的条目见 [HISTORY.md](HISTORY.md)，只在冲突处标注本节）。

判断一个需求算不算"本项目的正题"：**它的产物是不是一个"算出来的答案"？**
是 —— 那是计算器该做的；如果只是"把已经有的东西画得更好看" —— 那不是。

## 当前规划（未完成）

### 阶段 3 — 定理库 + 交互打磨（M3，进行中）

- **定理库 5 条已落地**（U17）：Sylow I / II / III + 轨道–稳定子 + 第一同构。
- 还差：**Cayley 定理** —— 它的舞台（`leftAction(G)`，G 左乘作用在自身上）已经可用，
  但"G 同构于 S_n 的一个子群"这一步在图上**没有落点**（要造 `Sym(Ω)` 这样的置换群对象，
  而 S₆ 已 720 阶、S₂₄ 建不出来）。得先想清楚"忠实作用 ⇒ 嵌入"画成什么，
  否则又是一张只有自环的图。候选做法：把"作用的核"变成一等对象。
- 交换图画布打磨（对齐 Desmos 简约感）：**轨道–稳定子的图目前是两条斜线**
  （`Orb` 与 `Stab` 同层，但与 `G` 不同列）——布局算法还没有"一个顶点带多个下层产物"的规范。
- 里程碑：定理库 5+ 模板 ✅（已达），剩下的是打磨。
