## 第十五批（U35）—— 商群的商群 / 第三同构（用户：「同构第三定理做不了，不能做商群的商群」）

- **触发**：`G=S4, H=A4, N=V4`（N 独立构造）→ `A=H/N`、`B=G/N`、`D=G/H` 都对，写 `F=B/A` 报
  「A 与 B 是两个各自构造的群，元素记号碰巧重合……B 里与 A 同构的正规子群恰有一个：闭包(B, 234, 124, 132, 143)」。
- **根因（探针实锤）**：**同一批陪集成员，core 在不同母群里给的 label 口径不一致** ——
  A₄ 的商里是 `(234)`、`(124)`…（带括号），S₄ 的商里是 `234`、`124`…（不带括号）；
  陪集只留 label（没留 id），`elementSemanticKey` 直接按 label 比 → 同一批陪集成了两批 → 对齐失败。
  两边陪集 id 又都是 `qcoset-i`（撞号）⇒ 分诊误判成"记号碰巧重合"（`idsAllIn=true` + `idsComparable=false`）。
- **改法**：新增 `gal/semantic.ts`（`canonicalMemberLabel`：置换记号唯一化——轮换从最小元起、
  轮换按首元排序；`(12)(34)` / `(0,1)` / 非置换记号都不会被误认）+ `elementSemanticKey` 搬过去
  （ops 与 relations 两份消费者共用，避免 ops↔relations 循环依赖）。
  **`relations.containment` 第①关**从"按 id"升级为"**按语义键对齐**"：普通元素退化成 id 比对
  （行为与从前完全一致），陪集按成员集合比。
- **连带（都是判据修好的自然结果）**：① 真包含 `A₄/V₄ ≤ S₄/V₄`（正规、指数 2）判得出来；
  ② 假的 `S₄/A₄ ≤ S₄/V₄`、`F ≤ B`、`F = D`（id 撞号的产物）消失；
  ③ `derive` 的 `KN ↪ GN` 标签从 `↪` 变 `⊴`（本组 K ⊴ G、指数 2 —— 标签一直是现场判定的）。
- **回归**：语义层 **1356/1356**（`suites/thirdIso.ts` +9：独立 N 那条链 + 上面三条连带）
  · 走查 **615/615（21 套）**（`e2e/third-iso.mjs` 5 → 8：浏览器里跑 S₄/A₄/V₄ 链、F₂ 识别 C₂）
  · `tsc` 零错误。截图 `docs/assets/u35-third-iso-quotient.png`。
- **教训**：**label 是展示形态、id 才是身份**这条老规矩，在 core 的商群元素上不成立
  （陪集只有 label）；而 label 的**写法又随母群变**。跨群比"同一个元素"必须用**规范化后的语义**。
